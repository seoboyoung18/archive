# H1 효과음 S2 게임 연결 검수

2026-10-03. `main/d0a0d15`의 깨끗한 작업 트리에서 시작했다. 사용자 “다음 진행하자”와 초기 **소리 켜짐·음량30%** 선택에 따라 [S v0.3](../specs/h1-sound.md)을 구현했다. 기존 s1-v1 WAV9종·전투 수치·입력·CPU 선택은 유지했다.

## 구현과 수명

- 명중/방어와 붙잡음·H36 충격·풀기는 공통 전투의 실제 사건을 소비한다. 기본기 첫 회복F에 같은 공격ID가 살아 있고 접촉하지 않은 경우만 `WhiffEvent`를 낸다. 같은F 피격/잡기 취소·실패 잡기에는 헛침음을 추가하지 않는다.
- `CombatSoundCursor`가 매 논리틱을 읽고 세션/소유자/ID/종류로 중복을 막는다. 한 렌더의1~5틱을 각각 처리하고 결과 진입 마지막 사건도 소비한다. 결과 화면의 보존 사건은 다시 내지 않으며 기록은 활성 동작과 최근 틱만 유지한다.
- 게임 전용 `CombatAudio`는 개별 Web Audio 노드로 동시/연속 소리를 겹쳐 재생한다. S1 미리듣기의 이전 조합 교체 방식과 분리했다. 음원 fetch/디코딩은 Phaser 필수 이미지 로딩과 독립적이다.
- 준비 지연·잠금·음소거·음량0·정지·파일 실패 당시 사건은 소비 후 폐기한다. 비동기 준비가 끝나도 지난 사건을 되살리지 않는다. 정지/포커스 이탈/새 세션/음소거는 활성 노드와 늦은 활성화 요청을 취소한다. 마지막 종료음은 별도 중단이 없다면 완료한다.
- 두 화면의 켜기/끄기·0~100% 설정은 페이지 내 초기화/라운드/재경기에도 유지한다. 새로고침은 켜짐·30%다. 설정 조작은 게임을 정지한 채 오디오를 준비할 수 있고 게임의 계속하기 동작으로 재개한다. 활성화/실패 안내와 접힌 개발용 수치를 제공한다.
- 독립 검토에서 실제 연결의 추가 결함은 발견되지 않았다. 구현 도중 정지 상태의 켜기/음량 조작이 활성화까지 막히는 경로를 보완했다. 명시적 오디오 준비는 허용하되 정지 중 재생은 막으며, 이후 새 정지는 대기 중 요청을 다시 취소한다.

## 자동 검증

- 전체 **260/260**: 기존197 + 사건25 + 소비기15 + 오디오19 + 통합4. 새로운 헛침 사건 검사는 구현 전 실패를 확인했다. 나머지 새 검사 전체의 사전 실패를 주장하지 않는다.
- 사건: 선/앉은8공격과 양쪽 명중/방어/헛침 경계, 같은F 타격·잡기 취소, C 연계, 실패 잡기, H0/H12/H36, 마지막 KO/동시 KO/시간 종료.
- 소비/재생: 소유자 간 같은ID·새 세션/동률 재경기, 각1~5틱,20,000틱 기록 정리, 같은 슬롯 동시 노드, 늦은 resume/decode·파일/기기/노드 실패, 정지·꺼짐·0·폐기·종료 노드 정리. AudioContext는 자동 검사에서 가짜 장치로 대체했다.
- 통합: 실제 전투/경기→소비기→오디오의 C 음소거/파일 지연, 마지막 H36 KO/시간 종료 헛침, 잡기 도중 정지/재개, 같은 라운드 재경기를 검사했다. 오디오 없는 참조 전투와 매틱 상태를 비교해 체력·시간·결과 불변을 확인했다.
- `npm run build`의 타입 검사/빌드 통과. 기존 Phaser500kB 청크 경고는 유지한다. `verify:sounds`, 생성 `--check`의 WAV9+reel+manifest11파일 바이트 재현,5개 unity 혼합, `verify:assets`의 기존100포즈 검사 통과. 에셋과 의존성은 변경하지 않았다.
- 문서55개·상대 링크357개 누락0·공백 검사 통과. [지정 Notion](https://app.notion.com/p/3eca2fe05e6881c29eabd7435a688947)의 S2 기록도 저장 후 재조회로 확인했다.

## 브라우저 확인

내장 브라우저의 실제 빌드 `127.0.0.1:4174`에서 UI와 키 입력을 사용했다. 전투 상태/체력/시간을 주입하지 않았다. 근접 배치는 기존 검수 기능이므로 이동 접근과 구분한다.

- 표적 초기 켜짐·30%, 시작 전 오디오 미생성/재생0. 시작 후 `running`·준비9/9.
- 근접 U+I로 CPU100→82, 붙잡음/충격 총2회·폐기0·완료/정지 뒤 실행0. H34에서 정지/재개한 경우도 과거 붙잡음이 재생되지 않고 충격만 추가됐다.
- ‘잡히면1회 풀기’에서100/100 유지, 붙잡음/풀기 총2회·폐기0. 실제 정확한 H0 물리 입력 성공과 구분한다.
- 근접 약손으로 CPU100→92, 명중음1회·폐기0. AI 경기의 실제 U 헛침도1회·폐기0으로 확인했다.

- 선 뒤 방향 표적에서 약손 방어·피해0, 방어음만1회·폐기0. 이후 표적이 걸어서 멀어졌으므로 헛침과 혼동하지 않도록 마지막 타격 문구와 소리 슬롯을 함께 확인했다.
- 효과음을 끈 채 약손 명중100→92에서 재생0·폐기1. 다시 켜면 게임 정지 유지·소리 준비됨·재생0으로 지난 타격을 재생하지 않았다.
- 켜짐 상태의 음량0에서도 새 근접 세션과 실제 약손 명중100→92를 확인했다. 근접 배치 후에도0% 유지,30% 복원 뒤 게임 정지·재생0·폐기1·실행0이었다. 이후 검수 초기화는 켜짐/30%와 준비9/9를 유지하고F0·100/100·세션7·재생/폐기/실행/기록0으로 돌아갔다.
- AI 경기에서 실제 CPU 접근·타격으로 PLAYER100→70, PLAYER 헛침을 포함해 총4회·폐기0·최근 약발 명중을 확인했다. Esc 정지 후 실행0. 두 대상 탭의 warn/error0.

## 한계와 다음 확인

브라우저의 `running`·재생/완료 횟수는 실제 귀로 듣는 검증이 아니다. 출력 장치의 음색·왜곡·소리 구분·겹침·지연·반복 피로도, 독립 Windows Chrome/Edge는 미확인이다. 실제 모든 자동 경계/최종 KO/동률 재경기/오디오 실패를 브라우저에서 재현하지 않았다. 숨김/포커스 이벤트 연결과 자동 취소 검사를 실제 탭 이탈·복귀 성공으로 보고하지 않는다. CPU는 기존 기본기 전략을 유지하고 잡기·풀기를 새로 선택하지 않는다.
