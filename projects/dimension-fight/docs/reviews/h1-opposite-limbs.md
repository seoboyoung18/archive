# H1 약·강 손발 및 강공격 전신 회전 검수 · 2026-10-02

## 적용 결과
[수정 명세](../specs/h1-opposite-limbs.md)에 따라 선 강손6·선 강발8·앉은 강손6·앉은 강발6포즈를 교체했다. 기존 약공격과 반대인 가까운 뒤쪽 팔/빨간 옆선 다리로 공격한다. 강손은 뒤꿈치 들기와 허리·어깨 회전, 강발은 반대 지지발 피벗과 골반 회전·회수·착지로 구성했다. 전투 시간·피해·판정과 런타임75포즈는 유지한다.

내장 ImageGen으로 만든 원화39장(중단 전 보존2장 포함) 중26장을 선택했다. 정확한 프롬프트9개 JSON과 후보는 `assets/characters/h1/generated/opposite-limbs-v1`, 정렬 출력·해시 manifest는 `assets/characters/h1/derived/opposite-limbs-v1`에 있다. 승인된 비율 유지 축소·투명 여백 배치만 스크립트로 수행했다.

## 제작 중 수정
- 발 고정 조건의 초기 강손2장은 사용자 전신 회전 요청 이후 제외했다.
- 강발 유효 후보의 여분 팔/소매를 다시 생성해 정확히 두 팔인 v3를 선택했다.
- 앉은 강손 마지막 회복에서 주먹이 다시 뻗는 후보를 제외했다.
- 선 강발 정점의 지지발 이동, 하강의 발 방향 역행, 앉은 강발 준비의 잘림과 회복 시 몸 확대를 재생성했다. 정점 v2는1196×1315로 규격도 달라 제외하고1254×1254 v3를 사용했다. 검사 기준을 완화하지 않았다.
- 생성 중 실행 환경 종료로 저장되지 않은 작업은 파일 존재를 확인해 재개했다. 완료 순서로 이름을 추측해 연결하지 않았다.

## 실제 검증
- `npm run verify:assets` 통과.26장 모두512×512 RGBA·투명 가장자리·원본/출력 해시 일치·공통384/1120배율·루트(256,448). 하단447, 앉은 포즈 상단191~221.
- `npm test` 60개 통과.75개 파일 존재, 강공격26개만 새 경로로 변경, 기존 비교용 파일 존재와 모든 공격 프레임별 구간/종료·피해·방어·KO 회귀 확인.
- `npm run build` 타입 검사·정적 빌드 통과. 기존 Phaser 청크 크기 경고가 남는다.
- 내장 브라우저에서4종의26포즈 연락판, 약/강4쌍의 실제 그림을 확인했다. 강손은 흰 상의 앞을 가로지르는 팔, 강발은 빨간 옆선 다리와 반대 지지발로 구분된다. 골반/상의 방향과 뒤꿈치/발끝 회전도 이전 그림과 다르다.
- 선 강손10F 유효, 앉은 강발0.25배 재생 후15F 유효·정지, 좌우 반전을 확인했다. 비교 화면은 실제 전투 포즈 선택 함수를 사용한다.
- 새 전투 탭에서75개 에셋 로딩·대기 렌더·정지 확인. warn/error 없음. 시작→K→Esc 입력은F0에 머물러 실제 타격 성공으로 보고하지 않는다. 피해/판정 검증은 자동 테스트 결과다.
- 기존 비교 탭에는 개발 서버 재시작 전 Vite WebSocket 연결 실패 기록이 있었다. 재시작 후 수동 새로고침으로 최신 화면을 확인했다. 탭의 전체 로그가 오류0이었다고 보고하지 않는다.

## 남은 품질·미확인 범위
강손·강발의 팔다리 구분과 전신 회전은 반영됐지만 전체 자연스러움 최종 승인은 별개다. 선 강발 들어올림/마지막 복귀의 상단48은 기본 자세64와 차이가 있어 몸 높이 변화가 남는다. 준비→회전→회복의 지지발 재배치와 마지막 기본 자세 전환도 추가 체감 검수가 필요하다. 발 피벗을 의도적으로 허용하므로 발 윤곽100% 겹침을 품질 완료 조건으로 삼지 않는다.

이번에 전체 대전·Chrome/Edge 독립 검증·새 그림의 모든 실제 타격/코너 관계는 확인하지 않았다. 기존 KO 경계 잘림도 남는다. 경기·콤보·잡기·효과음 상세 명세는 승인 대기다. 원격 push는 수행하지 않았다.
