# B1 대기·보행 R1 시안 검수

2026-10-06 · **시안 제작, 게임 적용 보류**

[B1 포즈 명세](../specs/b1-pose-r1.md)의 첫 제작 단위인 대기 4장과 보행 24장을 [재생 비교 화면](evidence/b1-walk-r1.html)에 배치했다. 보행은 `walk-00 → walk-mid-00 → … → walk-11 → walk-mid-11` 순서로 2F씩, 총 48F·0.8초를 반복한다. 대기는 `idle-0 / idle-in / idle-1 / idle-out`을 각각 8/7/8/7F로 표시한다. 느린 재생과 한 장씩 넘기기를 지원한다.

## 제작·검증 결과

- B1 원본 `reference.png`와 R0 정렬본을 기준으로 built-in ImageGen을 이용해 오른쪽 방향의 전신 투명 PNG 후보를 만들었다. 원화는 `assets/characters/b1/generated/r1-v1/`, 정렬 결과는 `assets/characters/b1/derived/r1-v1/`에 있다. 탈락 후보는 `generated/r1-v1/rejected/`에 보존했다.
- [정렬 스크립트](../../scripts/normalize-b1-r1.ps1)는 원화를 다시 그리거나 자르지 않는다. 보행은 R0의 고정 배율, 대기는 투명 여백 차이를 보정하기 위한 R0 가시 높이 375px를 적용한다. 전부 512×512 RGBA로 출력하고 알파 8 이상 최하단을 y447로 맞춘다. 원본·파생 SHA와 실제 경계는 [manifest](../../assets/characters/b1/derived/r1-v1/manifest.json)에 기록했다.
- 최초 보행 04는 양발 지지로 굳어 보여 한쪽 발을 드는 그림으로 교체했다. 09는 지지발이 갑자기 바뀌던 구간을 양발 접지로 교체했다. 11→00 루프 구간의 중간 그림은 앞발 착지를 보이도록 교체했다. 이전 그림 3장은 `rejected/`에 남겨두었다. 최초 06의 양팔 교대 실패본도 그곳에 보존했다.
- 로컬 브라우저에서 보행 25개 이미지(무대 1+연락판 24)의 로딩을 확인했다. 대기 4장과 보행 24장 모두 연락판에서 표시됐다. 이 검증은 **이미지 로딩과 배치**만 확인하며, 자연스러움의 최종 승인은 아니다.
- 정렬 스크립트를 다시 실행해 manifest SHA가 그대로임을 확인했다. 변경 파일의 상대 링크와 `npm run build`도 통과했다. 빌드의 기존 큰 청크 경고는 유지된다.

## 남은 시각 검수

- 보행 03·04는 차이가 작고, 06~08은 손과 발의 단계 변화가 약하다. 24장으로 늘렸어도 해당 구간의 실루엣이 충분히 움직이는지 사용자 검수가 필요하다.
- 보행의 가시 영역 상단은 y61~82로 최대 21px 차이다. 실제 머리·어깨 높이 변화와 발 미끄러짐은 한 장 넘기기·느린 재생에서 재확인해야 한다. 각 프레임의 발 최하단 y447 일치는 **지지발의 수평 고정**을 증명하지 않는다.
- 대기 생성 원화는 같은 캐릭터인데도 투명 여백·그림 크기가 달랐다. 정렬 후 네 장의 가시 영역은 모두 y73~447이지만, 양발의 좌우 위치와 팔·꼬리 선이 완전히 고정되는지는 미확인이다. 따라서 `idle` 4장도 게임에 연결하지 않았다.
- 12개 최초 보행 핵심 그림의 정확한 생성 프롬프트는 제작 당시 파일로 보존하지 못했다. 이후 만든 중간·대기 16장과 재생성한 11→00 연결 프롬프트는 [prompts.json](../../assets/characters/b1/generated/r1-v1/prompts.json)에 남겼다. SHA로 원화 자체는 추적할 수 있다.

선택·전투 화면, B1 능력치, 공격·잡기·피격 그림, CPU 캐릭터 선택은 이번 시안에 포함하지 않는다. 사용자 모션 검수와 전투 정의가 끝나기 전에는 B1을 선택 가능 상태로 표시하지 않는다.
