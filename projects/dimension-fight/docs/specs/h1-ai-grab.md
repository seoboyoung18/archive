2026-10-03 · AI-G v0.1 · **사용자 승인·구현 완료**. C/G/S2가 연결된 `94c9eff` 이후 사용자 “다음 진행하자”에 따라 남은 대전/방어 대응을 검토했다. `2829de2`의 상세안 확인 질문에 사용자가 **“이 안으로 구현 (권장)”**이라고 답해 아래 A1~A4 및 세부 규칙을 구현 기준으로 확정했다. [AI v0.1](h1-ai-match.md)의 기존 기본기/관찰/수명 규칙에 잡기·풀기 선택을 확장했다. 전체281개·타입/빌드와 검증 범위는 [구현 검수](../reviews/h1-ai-grab.md)에 기록한다. 실제 사람의 난이도·청취 체감은 미확인이다.

## 목적과 승인한 내용

구현 전 CPU는 아래+뒤를 계속 유지하는 PLAYER에게 피해를 주지 못하고, PLAYER의 성공 잡기를 풀지 않았다. [기준 재현](../reviews/h1-ai-grab-baseline.md)에서 두 상황을 수치로 확인했다. 기존 메치기와 풀기 입력을 CPU도 사용하게 해 플레이어가 공격·이동·방어·잡기 풀기를 선택할 이유를 만드는 것이 이번 목적이다. 인간 승률·재미·난이도가 검증됐다는 의미는 아니다.

| 항목 | 승인한 규칙 | 플레이 영향 |
|---|---|---|
| A1 잡기 선택 | 보이는 앉은 자세 또는 선 방어/후진에 잡기 거리까지 접근하고, 지상 자유 상태의 상대에게 U+I | 아래+뒤 유지에 CPU가 기존 메치기로 대응 |
| A2 시도 간격 | 잡기 입력부터 최소120F(2초) 동안 다음 잡기 시도 금지 | 사이에는 기존 기본기·방어를 사용. 실패·풀려도 대기 적용 |
| A3 풀기 선택 | CPU가 관찰한 성공 잡힘의 두 번째·네 번째…에만, 첫12F 판단 때 새 U+I 한 번 | 첫 잡힘은 그대로 허용하고 이후 번갈아 풀기를 시도. 매번 완벽하게 풀지 않음 |
| A4 유지 범위 | 기본기 수치·12F 판단·C/G/S2 공통 규칙 유지 | CPU 콤보·점프·난이도 선택·랜덤·새 기술/그림/음원은 추가하지 않음 |

A2의120F와 A3의 첫 잡힘 허용·짝수 잡힘 풀기를 포함한 A1~A4가 위 응답으로 승인됐다. 기존 잡기 거리96·피해18·H0~12 풀기·H36 충격·H54/72 복귀는 유지한다.

## 관찰과 입력

- 기존12F 고정 판단과 판단 사이 방향 유지, 공격1틱 펄스를 유지한다. PLAYER의 이번 갱신 키·유지키·예약·미래 결과·체력/승수는 읽지 않는다.
- 기존 공개 위치·자세·행동·공격 구간에 현재 잡기 동작의 종류/역할/구간을 더한다. 풀기 가능 붙잡힘, 회전, 다운/기상 등 현재 표시되는 구간만 투영하며 상대의 손 이력·정확한 경직 잔여·미래 충격을 읽지 않는다.
- 붙잡힘/풀기 구간은 **쌍의 메치기 연출 H0~12**를 뜻한다. 대상 그림 하나는H19까지 붙잡힌 자세를 유지하므로 그 그림 이름만으로 풀기 가능 여부를 정하지 않는다. H13부터 공격자의 회전이 시작되는 현재 연출 구간을 함께 투영하고, 마지막 입력 허용은 기존 공통 판정이 결정한다.
- 현재 성공 잡힘의 관계 식별자(소유자+잡기ID)는 같은 잡힘의 중복 처리 방지에만 사용한다. 숫자 크기를 공격 횟수 추측이나 전략 선택에 쓰지 않는다. 새 전투는 AI 상태 전체를 초기화하므로 세션 간 같은ID가 충돌하지 않는다.
- 잡기/풀기는 `axis:0`, `crouch:false`, `jump:false`, `attacks:['lp','hp']`와 순서 있는 `handEvents: U↓ I↓ I↑ U↑`를 **한 논리틱**에 보낸다. 실제 겹침 뒤 두 손을 놓으므로 다음 틱에는 유지·반복 입력이 없다. 공격 배열만으로는 기존 짧은 단독 탭 해석 때문에 잡기가 되지 않는다.
- CPU도 같은 공통 전투 함수를 거친다. 성공·풀기·피해·위치·경직을 직접 만들거나 잡기 창을 늘리지 않는다. 기본기 슬롯의 짧은 단독 탭은 현재 계약을 그대로 사용한다.

## 판단 우선순위

1. 자기 성공 잡힘의 대상이며 붙잡힘/풀기 구간이면 아래 풀기 정책을 적용한다. 해당하지 않는 잡기 잠금(시도·공격자·회전·다운·기상·풀기 동작)은 기존처럼 중립이다. 잠금 중에도12F 판단 시계와 잡기 대기는 실제 전투틱마다 흐른다.
2. 자기 KO/공중/공격/피격은 현재 행동을 유지하고 새 행동을 예약하지 않는다.
3. 기존의 보이는 준비/유효 타격에 대한 방어와 자기 방어 경직 유지가 우선한다. CPU가 공격 중이면 새로 방어로 취소하지 않는다.
4. 상대가 성공 잡기의 대상 상태로 잠겨 있으면 대기한다. CPU가 H54에 먼저 복귀해도 상대가 H72에 기상 완료하기 전에는 접근·타격·재잡기를 하지 않는다. 이는 피해/기상 규칙 변경이 아니라 CPU의 선택이다.
5. 상대 공중이면 기존160거리의 접근/대기를 적용한다. 잡기 입력은 내지 않는다.
6. 다음 잡기 접근 조건이 맞으면 접근/대기/잡기를 선택한다.
7. 나머지는 기존 선 방어/후진의 앉은 발 우선과 기본8공격 순환/접근을 그대로 적용한다.

### 잡기 접근 조건과 실패

자기 지상 `free`, 잡기 대기 만료, 상대 지상 `free` 또는 `guard`이고 다음 중 하나가 보일 때만6번을 적용한다.

- 상대가 앉은 자세다. 숨겨진 뒤 입력 유무까지 판단하지 않으므로 단순 앉기에도 같은 선택을 한다.
- 상대가 선 방어 경직이거나 기존 명세의 보이는 후진 보행이다. 경계에 막힌 후진 그림도 같은 기준이다.

거리 `d > 96`이면 서서 상대 쪽으로 접근하며 기존12F 사이의 방향 유지/접촉 보정을 따른다. 거리 `d <= 96`에서 상대가 `free`면 새 잡기를 입력한다. 상대가 `guard`면 중립으로 기다린다. **방어 경직 중 대상은 공통 잡기 불가**이므로 남은 경직을 읽어 성공할 시점을 예측하지 않는다. 다음 판단에서 다시 조건을 평가한다.

접근 중 상대가 일어서거나 공격하면 다음 판단에서 기존 우선순위를 다시 적용한다. 잡기를 한 번 시작하면 기존 준비6/유효2/회복24F를 끝까지 적용하고, 실패할 것 같다는 이유로 취소하지 않는다. PLAYER는 거리 이탈·점프·유효 타격·성공 후 새 U+I 풀기 등 기존 대응을 사용할 수 있다. 같은F의 타격 우선·동시 잡기 상쇄도 공통 규칙을 따른다.

잡기 명령을 낸 틱을T로 두면 T+1~119에는 새 잡기를 내지 않는다. T+120부터 **기존 판단 차례이며 다른 자격도 맞을 때만** 다시 선택할 수 있다. 성공 여부와 무관하게 같은 대기를 적용한다. 접근만 하거나 경직 해제를 기다리는 동안은 대기를 새로 설정하지 않는다. 잡기 선택은 기본기 순환 커서를 바꾸지 않는다.

### 풀기 교대와 경계

- CPU가 자신을 대상으로 하는 새 성공 잡힘의 붙잡힘 구간을 **판단 시점에 처음 관찰**하면 횟수를1 증가시키고 그 관계를 처리했다고 기록한다. 홀수는 입력 없이 잡히고, 짝수는 그 판단에서 새 U+I를1회 보낸다. 같은 관계의 다음 판단에서 다시 시도하지 않는다.
- 첫 관찰 전에 PLAYER 입력을 보거나 H0를 예측하지 않는다. 정상12F 일정에서 최초 성공을 처리한 뒤 다음 관찰은 H0~11 상태이며, 명령은 다음 공통 갱신의 H1~12에 적용된다. 관찰H11→적용H12는 허용, 관찰H12→적용H13은 공통 판정에서 실패한다. 쌍의 구간 투영과 관찰→입력 적용 경계를 각각 자동 검증하며 대상 그림의H19 전환과 혼동하지 않는다.
- 실패한 잡기, 동시 유효 잡기 상쇄, H0 즉시 풀기로 성공 잡힘이 남지 않은 경우는 횟수에 넣지 않는다. 이미 내고 있던 유효 입력의 공통 상쇄는 별도로 적용된다.
- 풀기 입력은 잡기 시도 대기를 설정하거나 초기화하지 않는다. 기존에 남은 CPU 잡기 대기는 계속 감소한다. 풀기에 실패해도 같은 관계에서 재시도하지 않는다.
- 관계 식별자와 마지막 처리 여부는 현재/마지막 관계1개만 보관한다. 매 판단을 누적하는 목록은 만들지 않는다.
