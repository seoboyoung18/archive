# H1 전투 판정 구현 단계

초기 단계(2026-10-01): [승인된 전투 v0.3](h1-combat-draft.md)의 기본 판정을 구현하는 명세다. 아래 초기 단계 기록은 당시 범위이며 이후 화면·경기·AI 진행은 각 후속 문서를 따른다.

최신 반영(2026-10-03): 승인된 [전투 확장 v0.2 §6](h1-combat-expansion.md)의 C 콤보를 구현했다. 기본 공격 수치는 유지하고 공격 중 예약/회복 취소에 지정 예외만 허용한다. 총111개 검사와 실제2/3타 입력 결과는 [콤보 검수 기록](../reviews/h1-combo.md)을 따른다. G 잡기·3F 손 지연·S 효과음은 승인 대기다.

## 범위와 완료 기준

화면에 연결하기 전에 선/앉은 공격8종·뒤 방향 방어·경직·밀려남·공중 피격·동시 타격·KO 후 정지를 순수 TypeScript 함수로 구현하고 자동 검증한다. 기존 이동/시안 화면과16포즈는 보존한다. 남은25포즈 생성과 애니메이션 연결, 타이머·승수·AI·브라우저 전투는 후속 단계이며 완료로 표시하지 않는다. 없는 포즈를 대기 그림으로 대체하지 않는다.

- U/I/J/K의 새 누름만 공격 명령. 자유 상태의 다중 입력은 강발>강손>약발>약손. WASD 상쇄 후 자세를 결정하고 공격이 점프보다 우선한다. C 예약 입력의 다중키는 모두 버리며 올바른 기존 예약은 유지한다.
- 준비/유효/회복은 명세의 반열린 구간. 시작 갱신 나이0, 다음 갱신부터 증가하며 총 길이에 도달한 갱신부터 새 행동이 가능하다.
- 타격은 양 축의 양수 겹침일 때만 발생한다. 좌향 판정은 루트 기준 반전한다. 공격 인스턴스별 선수ID 이력에 방어도 기록한다.
- 이동/접촉 이후 양쪽 판정을 같은 스냅샷에서 수집하고 피해를 함께 적용한다. 피격으로 취소되는 공격도 해당 갱신의 유효 타격은 처리한다.
- 공격과 피격은 자세·방향을 잠근다. 방어 경직은 현재 아래 입력으로 자세를 바꿀 수 있고, 뒤를 놓으면 후속 공격을 자동 방어하지 않는다. 피격 중 재타격에는 새 경직을 적용한다.
- 경직N은 피격 처리 이후 N번의 갱신 동안 행동을 막는다. 잔여0으로 끝난 갱신까지 막고 그 다음 갱신부터 행동한다. 해당 기간의 공격/점프 펄스는 소비하고 예약하지 않는다.
- 공격/경직 중 수평 입력은0, 공중 중력은 유지한다. 공중 공격·방어·예약 공격 없음. 지상 공격 중 예약은 C 지정 연계만 예외다. 공중 피격 자세는 선 자세이며 착지 후에도 피격 자세를 경직 만료까지 유지한다.
- 체력0은 KO 우선. 양쪽 타격을 모두 적용한 뒤 종료 표시를 만들고 이후 갱신은 모든 전투 상태를 그대로 반환한다. KO 연출·시간 종료·승수는 경기 계층의 후속 책임이다.
- 잘못된 공격 구간/수치/사각형은 전투 생성 전에 오류로 거절한다. UI 실패 안내는 화면 통합 때 연결한다.

## 설계·정합성

`src/characters/h1.ts`에 승인 수치와 자세별 공격 데이터를 둔다. `src/combat/combat.ts`는 캐릭터 정의를 받아 전투 상태를 생성·갱신한다. 기존 `stepMovement`로 중력/이동/선수 접촉을 처리하고 행동 잠금은 전투 계층에서 적용한다. 정의는 공유하지만 체력·공격ID·상대 이력은 선수별로 독립적이다. 입력 모듈은 기존 이동 입력을 합성하여 U/I/J/K 펄스를 더한다. Phaser·DOM·새 패키지는 추가하지 않는다.

전투 함수는 실제 처리한1F당 한 번 호출한다. 재생용 포즈 구간 조회와 타격 유효 구간은 같은 공격 나이를 사용한다. 8공격의 그림ID와 실제 파일 연결은 이미지 검수 이후 한다.

## 실행 계획·검증

1. 데이터8종을 원문 표와 대조하고 잘못된 값의 거절 경로 작성.
2. 입력/상태/판정 구현 후 준비·유효 첫/끝·회복 경계, 미접촉/1px 겹침/좌우 대칭 테스트.
3. 단타 중복·방어9조합·자세 고정/변경·경직 정확한N회·취소/동시 타격·공중/코너/KO 불변 테스트.
4. 실제 키 이벤트에 해당하는 입력 기록으로 유지/반복/다중키/초기화와 예약 없음 검증. 여러 렌더 간격에서 같은 논리 입력 기록의 결과 비교.
5. 기존15테스트 회귀·타입 검사·빌드·에셋 검사 후 검수 결과/개발일지/계획 동기화 및 기능 커밋. 실제 브라우저 전투 확인은 미수행으로 남긴다.

## 2026-10-03 C 콤보 추가 범위·설계·검증 계획

- 선 U에서만 연계에 진입한다. U age3~12의 I를1개 예약하고 비방어 명중 후age9~12에 선 I로 취소한다. 그 연계 I에서만age5~22의 J를 예약하고 비방어 명중 후age13~22에 선 J로 취소한다. 각 창은 양 끝을 포함한다. 새 공격은age0·새ID·빈 타격 이력을 사용하고 선 자세/방향을 유지한다.
- 기존 `CombatInputBuffer`는 물리 키의 새 누름을 즉시 전달한다. 지정 예약·단계·비방어 명중 자격은 순수 전투 실행 상태가 관리하고 허용된 경로/창은 캐릭터 정의에 둔다. G 손 판독/3F 지연을 이번 입력 흐름에 넣지 않는다.
- 기존 공격 나이를 증가시킨 뒤 예약과 취소를 판독한다. 동일 갱신 명중 즉시 취소는 없고, 후속 공격을 시작한 갱신에는 나이를 다시 증가시키지 않는다. 방어를 포함하는 접촉 이력만으로 명중 자격을 판정하지 않는다.
- 방어·유효 종료까지 헛침·피격/상호 타격에서 자격/예약을 제거한다. 창 만료나 정상 회복 이후 예약 공격을 실행하지 않는다. 정지는 예약키만 비우고 공격·단계·명중 자격은 보존한다. KO/시간 종료·라운드/경기 초기화는 연계 정보 전체를 정리한다. 최종 포즈/마지막 피해 사건은 바꾸지 않는다.
- 피해8/12/10, 밀려남24/36/32, 준비·유효·정상 회복·사거리·경직은 유지한다. 중앙의 첫 접촉 거리110 미만에서3타,136 미만에서2타가 가능한 계산을 실제 공통 함수로 확인한다. 양쪽 코너·반전과 각 경계는 별도 검증한다.
- CPU는 기존12F 공개 상태 판단과 기본기 선택을 유지하고 공격 중 후속 입력을 생성하지 않는다. 순수 전투 규칙은 양쪽 공통으로 검증하며 CPU가 PLAYER 예약을 관찰하도록 넓히지 않는다.

캐릭터 연계 정의/검증 → 전투 예약·명중·취소 → 경기/표적 화면의 정지·종료 정리 → 기존 그림 연결/조작 안내 순서로 구현했다. C01~C05의 로직 경계를18개 새 테스트로 검사했고 기존93개 회귀·타입·빌드·75포즈 에셋 검사도 통과했다. 실제 키/화면에서2타·3타 명중과 정지/초기화를 확인했다. 자연스러움의 최종 체감 승인은 별도이며 수행 범위는 [검수 기록](../reviews/h1-combo.md)에 구분한다.
