## 현재 코드와 변경 범위

현재 `CombatInputBuffer`는 한 논리 갱신의 새 공격키 집합만 전달하고 바로 비운다. 두 손을 누른 순서·놓은 순서·실제 겹침을 알 수 없다. 마지막 유지 여부만 추가해도 한 갱신 사이에 눌렀다 놓은 겹침이 사라진다. 따라서 U/I의 순서 있는 누름/놓기 기록을 다음 논리 갱신에 함께 전달하고, 공통 전투가 손 판독을 수행하는 안이다.

캐릭터 정의에 잡기 수치, 선수 상태에 손 대기/잡기 시도/각자의 복귀 잠금, 전투 상태에 한 쌍의 성공 관계와 사건을 추가한다. 그림은 `h1-poses.ts`, 에셋 목록/검사는 기존 경로에 연결한다. 경기/표적 화면은 입력 정리·새 상태 표시·사용법만 확장한다. C 지정 예약·기본8공격의 수치·기존75포즈는 유지한다.

## 입력 판독 제안

F는60Hz 논리 갱신이다. 화면의 렌더 횟수나 실제 경과 밀리초로 손 조합을 판정하지 않는다. F0의 첫 손 입력 뒤 F0~F3 안에 반대 손의 새 누름이 들어오고, 그 누름 순간 두 손이 함께 눌려 있어야 조합이다. 반대 순서 I→U도 같다. OS 반복과 이전부터 유지한 손은 새 누름이 아니다.

물리 입력 순서는 갱신 사이에도 보존한다. 같은 갱신의 `U↓ I↓ I↑ U↑`는 유효한 겹침으로 판독하고, `U↓ U↑ I↓ I↑`는 겹침이 없어 잡기가 아니다. 실제로 겹쳤다면 뒤이어 두 키를 놓아도 이미 완성한 조합은 취소하지 않는다. 한 갱신에서 실행하는 행동은 최대1개다.

| 상황 | 제안 결과 |
|---|---|
| F0 U 유지, F3 I 새 누름 | 만료 판정보다 두 번째 손을 먼저 처리해 잡기age0 |
| F0 U 유지, F3까지 반대 손 없음 | F3에 선 U age0. F4 I는 진행 중 U에 대한 기존 C 규칙으로 판독하며 즉시 잡기로 변경하지 않음 |
| F0 U, F1 U 놓기 | F1 선 U age0. 같은F 눌렀다 놓은 단독 U는 그F에 시작 |
| F0 U, F1 I+K, U와I 겹침 | 유효 잡기 조합이 K보다 우선하며 그F 공격키 모두 소비 |
| F0 U 대기, F1 K만 새 누름 | 대기 손과 새 발 중 기존 K>I>J>U 우선순위로 K 실행. 손 대기 제거 |
| F0 I 대기, F1 J만 새 누름 | 기존 우선순위로 I 실행. 손 대기 제거 |
| 처음부터 U+J 또는 I+K | 유효 U+I가 없으므로 기존 우선순위의 기본기를 즉시 실행. 손 대기를 새로 만들지 않음 |
| 같은F에 겹치지 않은 U/I 누름 | 손 조합 없음. 기본기 다중키 우선순위로 I 실행 |
| 이전F의 U 대기 중 U↑→I↓, 발 입력 없음 | 기존 대기 U를 놓기로 확정하고 새 I는 버림. 이미 유지가 끝나 겹침 없는 조합 |
| C 공격 진행 중 U/I/J | G 판독을 거치지 않고 현재 C 지정 다음 키/창을 그대로 사용 |

손 대기는 행동 잠금이 아니다. 대기 중 방향 이동·뒤 방향 방어는 기존대로 가능하다. 피격/방어 경직에 들어가면 대기를 폐기한다. 그 뒤 키를 유지해도 공격을 재생하지 않는다. 새 판독에는 새 누름이 필요하다.

처음부터 점프와 공격을 함께 입력한 경우는 기존 공격 우선순위를 따른다. 지상 선 자세의 유효 W+U+I는 잡기로 W를 소비한다. W+단독 U/I는 W를 소비하고 손 대기를 시작하며 실제 손 공격age0은 놓기 또는F3부터다. W만으로 손 지연을 면제하지 않는다. 대기가 이미 진행 중인 다음F의 W 점프 또는 S 앉기 전환은 손 대기를 취소하고 해당 방향 동작만 수행하며 그F 공격키를 버리는 안이다(W+I+K도 같음). W/S 상쇄는 기존 이동 입력 규칙을 따른다.

처음부터 앉은 단독 손에는 지연이 없다. 앉은 상태의 같은F 새 U+I는 실패 조합으로 U/I만 소비하며, J/K도 있으면 남은 발 중 기존 우선순위로 앉은 발을 실행한다. 서로 다른F 손을 잡기로 예약하지 않는다. 공중·피격/방어 경직·잡기 잠금에서는 새 공격을 예약하지 않으며 잡힌 쪽의 풀기만 예외다.

기존 손 대기에서 유효 조합이 없고 발이 들어오면 놓기/만료보다 발과 대기 손의 우선순위를 먼저 적용한다. 새 반대 손은 실패 조합 뒤 별도 공격으로 이월하지 않는다. 따라서 대기 U를 놓은F에 I+K가 들어와도 K1회이며 U/I가 차례로 실행되지 않는다.

C의 나이는 실제 손 공격 시작부터 센다. F0 U를 유지하다F3에 U age0이 시작됐다면 F4/F5의 I는age1/2라 버리고 F6의 I는age3으로 예약한다. 반면 F0에 U를 눌렀다 놓아 즉시 시작하면 F3의 I가age3 예약이다. F0 U 유지→F3 I 겹침은 C가 아닌 잡기다.

현재 CPU/자동 입력의 기본기1F 펄스는 같은F의 누름→놓기 짧은 탭으로 정규화하는 안이다. PLAYER의 같은 순서 입력과 동일하게 조기 놓기로 처리해 기존 CPU 기본기 시작 시점을 유지한다. 이는 CPU가 손 대기 규칙을 우회하는 별도 즉시 공격 경로가 아니다. CPU 판단 간격/후보·C 후속 선택은 바꾸지 않는다.

CPU가 잡기 잠금에 들어가면 유지 방향/아래를 즉시 지우고 중립 입력을 낸다. 경기 진행 중12F 판단 시계는 계속 진행하되 잠금 중 후보를 선택하거나 순환 위치를 바꾸지 않는다. 자신의 잠금이 풀린 뒤 다음 예정 판단F부터 원래 선택을 재개한다. 상대의 H+30 해제와 잡는 쪽 H+36 해제를 따로 처리하며 PLAYER 손 대기/풀기 입력을 관찰에 노출하지 않는다.

## 잡기 시도와 성립

| 항목 | 제안 규칙 |
|---|---|
| 시도 자격 | 행동 가능한 지상 선 자세. 조합 인정F에age0·새 시도ID, 방향 고정 |
| 시도 시간 | 준비age0~5, 유효6~7, 헛잡기 회복8~31, age32부터 현재 입력으로 자유 행동 |
| 시도 중 | 이동·점프·방어·기본기/콤보 취소 없음. 일반 타격에 피격 가능하며 무적 없음 |
| 대상 | 고정 방향 앞의 지상 선/앉은 상대. 자유·일반 공격·잡기 시도(준비/유효/헛회복) 중 가능 |
| 제외 | 공중·KO·피격/방어 경직의 마지막 차단F까지·잡기 성공/복귀 잠금 |
| 거리 | 유효F의 실제 발 기준점 간 거리96 이하. 현재 최소 간격72, 뒤·아래+뒤 방어 무시 |
| 실패 | 두 유효F에서 성립하지 않으면 헛잡기 끝까지 진행. 기본 손 공격으로 되돌리지 않음 |

일반 공격처럼 기존 나이를 먼저 증가시키고 새 시도는age0에서 시작한다. 이동·점프·접촉 해결 뒤 같은 스냅샷에서 일반 타격과 양쪽 잡기 후보를 수집한다. 현재F 점프를 시작한 상대는 공중이므로 실패한다. 현재F 착지한 상대는 다른 자격을 만족하면 대상이 될 수 있다. 경직stun1→0인F도 여전히 차단F이므로 대상에서 제외한다.

일반 타격 접촉을 먼저 양쪽에 적용한다. 그F에 일반 접촉이 있으면 새 잡기는 없다. 접촉이 없고 양쪽 잡기가 동시에 성립하면 승자를 정하지 않고 동시 상쇄한다. 한쪽만 성립하면 그 관계를 한 번 만든다. 배열의 첫 선수를 먼저 잠가 두 번째 후보를 없애지 않는다.

## 성공과 풀기 시간표

성립F를H로 둔다. 양쪽 기존 공격·콤보·손 대기를 취소하고 서로를 바라보는 현재 방향과 잡힌 쪽의 선/앉은 자세를 보존한다. H에 입력된 키는 풀기로 재사용하지 않는다. 루트 위치의 순간이동·좌우 교대는 없고 밀려남은 충격F에만 적용한다.

| 시점 | 제안 동작 |
|---|---|
| H | 붙잡음 사건1회, 피해0, 양쪽 행동 잠금 |
| H+1~H+12 | 잡힌 쪽의 두 새 손 입력으로 풀기. 두 누름 모두 H 이후, 차이3F 이하·겹침 필요 |
| H+13~H+17 | 풀기 종료, 붙잡고 밀기 준비. 피해0 |
| H+18 | 충격 사건·피해18 단1회. 대상만 고정 방향으로48 밀고 무대 경계 제한 |
| H+19~H+29 | 살아 있는 대상의 복귀 잠금. 잡힌 자세 유지 |
| H+30 | 대상 행동 해제. 현재 입력/자세 적용, 잠금 때 입력한 공격은 재생하지 않음 |
| H+36 | 잡는 쪽 행동 해제. 상대보다6F 늦게 자유로움 |

풀기 조합이 완성되는 F가H+12면 성공, H+13이면 실패다. H 이전/H의 유지키나 한 손만 입력한 경우는 풀기가 아니다. 실패한 풀기 손은 기본기로 대체하지 않는다. 풀기 중 J/K는 쓰지 않으며 유효한 두 손 조합을 방해하지 않는다. 피해 시점의 체력에서18을 빼고0 아래로 내리지 않는다.

풀기 성공F를T로 두면 피해0·두 선수 각각 바깥으로16(경계 제한) 이동, T~T+11 복귀 잠금, T+12 자유다. 동시 잡기도 그 상쇄F를T로 하여 같은 분리/복귀를 적용한다. 이전 공격은 복원하지 않는다.

대상은H+30 이후 먼저 행동하므로 두 사람을 한 번에H+36에 해제하지 않는다. 각자의 잠금 만료를 관리하고 마지막 관계 정리는 이미 자유로워진 상대의 새 공격/콤보를 건드리지 않는다. 해제된 상대에게 타격받으면 남은 잡기 회복은 일반 피격으로 취소된다.

## 정지와 종료 처리

정지/포커스 이탈은 논리 나이와 역할·포즈를 유지하되 손 대기·풀기 입력·C 예약만 비운다. 재개 후 남은 창에 새로 누른 손만 판독한다. 유지된 키는 놓을 때까지 다시 받지 않는다.

마지막 경기F도 전투 사건을 먼저 반영하고 기존 KO 우선/시간 승패를 결정한다. H+18에서 시간이 끝나면 충격18을 반영하고, 그 직전 종료면 피해0이다. 충격 KO는 대상만 기존18F 쓰러짐으로 전환한다.

종료 후 실행 가능한 양쪽 잠금/예약/관계는 제거하고, 마지막 렌더용 역할·포즈는 종료 스냅샷으로 보존하는 안이다. 살아 있는 상대가 갑자기 idle로 바뀌거나 콤보의 마지막 기록이 지워지지 않게 한다. 시간 종료 후 뒤늦은 충격/풀기나 이동은 없다. 다음 라운드·재경기·전체 초기화는 종료 스냅샷까지 제거한다.

## 동작과 이미지 제작 제안

붙잡아 밀쳐내는 한 기술로 제한한다. 공격자는 대상의 선/앉은 자세에 맞춰 팔/상체 높이가 달라지는 성공 동작을 사용한다. 대상은 잠금 중 처음의 선/앉은 자세를 유지하고 풀기/충격 후 살아 있는 복귀를 보여준다. 기존 KO·기본기 그림을 새 동작의 대체물로 사용하지 않는다.

시도 준비→팔 뻗기→헛잡기 회수, 대상 자세별 붙잡음→밀기→복귀, 대상 자세별 붙잡힘→충격→복귀, 양쪽 풀기→복귀에 실제 그림이 필요하다. 구체 포즈 수와 각 중간 그림은 이 동작을 승인한 뒤 작은 접촉 시안에서 산정한다. 기존75포즈·원본·탈락 후보를 보존한다.

H+18에는 밀려난 대상의 몸을 계속 붙잡은 그림을 유지하지 않고 밀기 끝/손 분리로 보여준다. H+19 이후는 공격자 회수와 대상 충격/복귀, H+30/36은 각자의 자유 전환이다. 풀기는T에 손 분리, T+12 전에 각자의 복귀를 마친다. 그림 배분 때문에 논리 시간표를 늘리지 않는다.

기존 ImageGen 제작/편집·공통 축소/투명 배치 방식을 따른다. 출력512×512·발 루트(256,448)·표시0.625를 유지하고 포즈별 확대나 스프라이트 루트 이동으로 접촉을 숨기지 않는다. 각 선수 그림을 따로 저장하되 두 인물을 함께 놓은 연락판으로 접촉을 확인한다.

두 루트 사이 간격은 거리72/96에서 에셋 좌표115.2/153.6이므로 손 접촉 지점이38.4px 달라진다. 거리72/84/96, 선/앉은, 양쪽 코너/반전에서 손과 윗옷/상완이 닿는 영역을 검수한다. 단일 그림으로 성립 범위를 설명할 수 없으면 거리별 시안 또는 거리 제안을 다시 검토한다. 판정 거리를 이미지에 맞춰 몰래 바꾸지 않는다.

한 쌍이 붙잡힌 동안에는 잡는 쪽 인물을 앞에 그리는 안으로 양쪽 역할/반전을 검수한다. 팔만 따로 앞뒤로 교차시키는 분리 리깅은 추가하지 않는다. 분리 뒤에는 기존 선수 순서로 돌아가고 종료 스냅샷은 마지막 그리기 순서도 보존한다. 선/앉은 이름표와 피격 사각형은 그림과 같은 자세를 사용한다.

새 폴더를 포즈표에 넣는 것과 함께 `h1-assets.ts`의명시적 파일 수집 목록·manifest·`verify-assets.mjs`의버전/포즈 목록을 갱신한다. 포즈표만 추가해 로딩URL이 빠지는 상태를 검사한다. 최종 런타임 수는 채택한 그림 수로 갱신하며 현재75장을 새 제작 완료 수량으로 바꾸지 않는다.

## 구현 순서와 검증 기준

## 승인 전 검토 이력

현재 `main/f05a2ad`의 입력·전투·경기·AI·포즈 선택 코드를 읽고 독립 검토했다. 60Hz 기준3F=50ms,12F=200ms, 성공 후18F=300ms를 산술 확인했다. 조합 인정부터age6에 잡히면 충격까지24F(400ms),age7에 잡히면25F이며 첫 손의 조합 대기가 최대3F 더해질 수 있다. 18F는 버튼 입력부터의 시간이 아니다.

위 산술 검토 당시에는 G 로직/이미지가 없었으며 기존111개 통과는 C 구현의 근거였다. 이후 사용자가 “이 안으로 G 구현”을 승인하여 아래 구현을 적용했다. 승인 전 검토와 구현 후 검증을 구분한다.
