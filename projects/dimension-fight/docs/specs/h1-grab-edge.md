# H1 대기·방어·잡기 코너 표시 보완

최신 화면 규칙(2026-10-03): 사용자가 승인한 [거리 대응 카메라 A](h1-camera-framing.md)가 아래 개별/쌍 표시x 보정 규칙을 대체한다. 원래 메치기 곡선·높이·회전과 전투 시간표는 유지하고, 모든 그림·판정·이름표·배경에 공통 변환을 적용한다. 아래 수치와 검수는 해당 단계의 이력이다.

2026-10-03 · 사용자 “현재 대전 체감·화면 보완” 선택과 “다음 진행하자”에 따른 기존 잘림 보완. 전투 수치·입력·기술 시간표의 변경은 없다.

## 범위와 판단

앞선 [일반 피격·KO 보완](h1-reaction-edge.md) 이후 남은 대기·붙잡음·메치기 공격자의 잘림을 이어서 수정한다. 실제 PNG의 모든 alpha>0 픽셀 셀을 측정했다. 대기 두 장은 수평 합집합이 [105,414)이며, 방어 두 장도 코너에서 잘린다. 이번 범위는 대기2·앉기1·방어2와 현재 잡기/풀기/메치기에 선택되는19포즈다. 기존 일반 피격2·KO3 보정도 유지한다.

걷기·점프·기본 공격은 이번 표시 보정에서 제외한다. 걷기의 각 프레임을 따로 옮기면 주기 중 표시 루트가 흔들릴 수 있으므로 이동과 공격 전환의 발 정렬은 별도 검토한다. 이동 시안 화면과 원화100장도 유지한다.

## 표시 규칙

1. 논리 루트·피격/공격 판정·거리·피해·잠금·AI·소리·포즈 선택·배율은 바꾸지 않는다. 이미지와 이름표의 표시x만 화면0~1280 안으로 이동한다. 중앙에서는 기존 표시다.
2. 대기 두 장은 합집합 경계를 사용해 같은 논리 위치·방향에서 같은 표시x를 유지한다. 나머지는 현재 포즈의 실제 알파 범위를 사용한다. 모든 alpha>0 픽셀의 셀 끝을 포함하며 회전된 포즈는 투명 사각형 모서리가 아니라 실제 알파 셀의 볼록 껍질로 계산한다.
3. 기존 메치기의 기본 이동 곡선·높이·회전·원점·깊이를 유지한다. 대상만136~1144에 넣던 고정 보정과 그 보정에서 논리 루트로 돌아가던 보간은 아래 공통 규칙으로 대체한다. 새 보간 시간은 추가하지 않는다.
4. 같은 성공 잡기 또는 같은 풀기 관계로 양쪽 표시 잠금이 남아 있으면, 경계 보정 전 두 그림의 합집합을 구하고 같은 최소dx를 적용한다. 두 표시 중심 사이 거리와 접촉 구도가 독립 보정으로 변하지 않게 한다. 기존 원화의 접촉 정확도 전체를 새로 승인하는 것은 아니다.
5. 관계는 양쪽 `grabPoseState`의 같은 success/escape 종류, 반대 역할, 같은 공격자 ID와 serial, 같은 age 및 각 releaseAt 전 상태로 확인한다. 양쪽 live 또는 양쪽 종료 snapshot이어야 한다. 풀기에는 `grabPair`가 없고 성공의 H54~71에는 남아 있으므로 pair 유무만으로 묶지 않는다.
6. H54에 공격자가 복귀하면 독립 보정으로 바뀐다. 대상 H72 복귀 뒤에도 각자의 현재 포즈 규칙을 따른다. KO/시간 종료의 스냅샷은 같은 연출과 쌍 관계를 보존한다. 일반 KO 그림 선택과 보정에는 같은 결과 나이를 사용한다.
7. 정지 자세 사이, 또는 보정하지 않는 이동/공격으로 전환할 때 표시 보정량은 달라질 수 있다. 대기 주기 내 흔들림을 막되, 전환 전체의 무미끄럼이나 모든 포즈의 경계 해결을 주장하지 않는다.

## 구현·검증 계획

`combatVisuals(state, koFrame)`가 두 표시를 함께 계산하고 양쪽 게임 렌더러와 연결 검수 화면에서 사용한다. 단일 `combatVisual`은 개별 보정 검수용 호환 함수로 유지한다. 알파 메타데이터는 원화에서 사전 계산하며 런타임 PNG 디코딩을 추가하지 않는다.

실제 PNG를 독립적으로 읽는 검사로 좌우 경계·양 방향·거리72/84/96·선/앉은 대상의 H0~72, 잡기 시도·풀기·KO, H53/54와 H71/72 전환을 확인한다. 쌍의 동일dx, 중앙 불변, 스냅샷 고정, 논리 상태 불변, 대기 두 장의 루트 고정, 기존 피격·KO 회귀를 검사한다. 전체 테스트·타입·빌드 후 브라우저에서 기존 표시와 비교한다. 초기 위치를 지정한 입력 재현과 사람의 실제 대전 체감은 구분해 기록한다.
