# H1 약·강 공격의 팔다리 구분 수정 · 2026-10-01

## 요구사항·범위
사용자가 약손과 강손, 약발과 강발이 같은 팔다리를 쓰는 문제를 지적하고 전부 수정하도록 요청했다. 선 자세와 앉은 자세 모두 약/강의 공격 팔다리를 분리한다. 기존 약공격을 기준으로 강손/강발4종의 모든26포즈를 새 버전으로 제작한다. 이전 원화와 파생 파일은 보존한다.

## 외형 기준
오른쪽을 바라보는 기존 H1 기본 자세의 해부학적 연결로 구분한다. 화면 좌우 반전은 같은 캐릭터 전체에 적용하며 공격 손발을 바꾸기 위한 반전으로 사용하지 않는다.

| 공격 | 사용하는 팔다리 | 그림에서 확인하는 기준 |
|---|---|---|
| 선/앉은 약손 U | 앞손·먼 쪽 왼팔 | 화면 오른쪽 어깨에서 뻗는 기존 팔 |
| 선/앉은 강손 I | 뒤손·가까운 쪽 오른팔 | 기본 자세 화면 왼쪽 어깨와 연결, 흰 상의 앞을 가로질러 뻗음. 반대 손은 얼굴 가드 |
| 선/앉은 약발 J | 앞발·먼 쪽 왼다리 | 기존 줄 없는 쪽 다리로 공격, 가까운 빨간 줄 다리로 지지 |
| 선/앉은 강발 K | 뒤발·가까운 쪽 오른다리 | 빨간 옆선이 있는 다리를 회전시켜 공격, 반대 줄 없는 다리로 지지 |

좌우 명칭만 적어 생성하지 않고 어깨-팔꿈치-손목과 골반-무릎-발목을 직접 추적한다. 준비·유효·회수 도중 팔다리가 바뀌지 않아야 한다. 지지발을 먼저 정하고 체중을 이동한다. 정면 색만 바꿔서 반대 팔다리로 보이게 하지 않는다.

## 추가 요구사항: 강공격의 전신 회전
사용자는 강손뿐 아니라 강발도 몸·허리·발이 함께 돌아가야 한다고 명확히 했다. 팔/다리만 반대로 뻗거나 몸통을 기본 자세 그대로 고정한 그림은 부적합이다. 중단 전 프롬프트의 양발 위치·방향 고정 조건을 폐기하고 아래 기준으로 다시 제작한다.

- 강손: 준비에서 뒤쪽에 체중을 싣고, 뒷발 앞꿈치를 축으로 뒤꿈치가 들리며 골반이 돌아간다. 이어 허리·어깨가 회전하고 뒤손이 몸 앞을 가로질러 타격한다. 회수 때 회전을 풀어 원래 가드로 복귀한다.
- 강발: 반대쪽 지지발에 체중을 옮기고 발바닥 방향을 돌린다. 골반·허리가 열리면서 뒤쪽 공격 다리가 따라 나오고 상체 기울기·반대 팔로 균형을 잡는다. 접힌 무릎→다리 뻗기→회수→발 내려놓기→가드 복귀가 이어져야 한다.
- 앉은 강공격도 낮은 자세 안에서 골반·어깨 방향과 발의 회전을 보여준다. 낮은 상태를 유지하되 정면 몸통을 고정하지 않는다.
- 발의 의도적인 회전·뒤꿈치 들기를 허용한다. 원화 발 윤곽을 기본 자세에100% 겹치게 하는 기준은 강공격에 적용하지 않는다. 발바닥 접촉과 체중 지지, 의도하지 않은 미끄러짐을 구분한다.
- 그림 속 자세 회전이며 캐릭터 중심의 논리 이동이나 공격 판정 수치를 변경하지 않는다. 얼굴·옷·팔다리 정체성은 유지하되 가려지는 부위와 원근은 회전에 맞게 달라진다.

## 표시·설계
- 선 강손6, 선 강발8, 앉은 강손6, 앉은 강발6포즈. 키·표시 구간은 [이전 명세](h1-all-attack-frames.md) 그대로 유지한다. 전체75런타임 포즈 수도 유지한다.
- generated/opposite-limbs-v1에 원화·프롬프트·후보, derived/opposite-limbs-v1에26개 선택 출력·해시·변환값을 보존한다.
- 원화1254×1254, 출력512×512·루트(256,448)·공통384/1120배율과 표시0.625를 유지한다. 내장 ImageGen으로 그림을 제작하며 승인된 축소·여백 배치만 스크립트로 수행한다.
- 캐릭터 그림 경로만 새 버전에 연결한다. 공격 수치·타이밍·판정·이동·공통 전투 처리는 유지한다.
- 비교 화면에 약/강 유효 그림을 나란히 배치해 실제 팔/다리를 비교할 수 있도록 한다. 이전 강공격26장도 이전/현재 재생으로 비교한다.

## 제작·검증 순서와 완료 조건
1. 강공격4종의 유효 포즈를 먼저 제작해 약공격과 반대 팔다리인지, 골반·상체·지지발이 함께 회전했는지 확인한다.
2. 확인된 유효 포즈와 기존 기본 자세를 기준으로 나머지22장을 제작한다. 같은 손발이 이어지지 않거나 크기·얼굴이 달라진 후보는 제외/재생성한다.
3. 모든26장 RGBA·해시·공통 배율·기준점·잘림 검사.75경로와 기존60개 회귀 검사·타입/빌드.
4. 실제 그림에서4쌍의 약/강 반대 팔다리와 전체26장 연결, 왼쪽 반전과 구간 경계를 확인한다. 파일명/메타데이터만으로 그림의 손발 검증을 통과 처리하지 않는다.
5. 명세·결정·개발일지·검수 기록·Notion 동기화와 기능 커밋. 최종 자연스러움 승인과 실제 대전 검증 범위는 구분한다.

26포즈 교체·60개 테스트·에셋/타입/빌드 검사와 브라우저 그림 비교를 수행했다. [검수 결과](../reviews/h1-opposite-limbs.md)에 선택 원화·재생성 사유·실제 증거·남은 높이/지지발 연결과 실제 타격 검증 한계를 기록한다. 최종 자연스러움 승인으로 간주하지 않는다.
