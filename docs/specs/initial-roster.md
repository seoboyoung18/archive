# 첫 3명 선택·대전 v0.1 · 검토 초안

2026-10-06. **B1·R3의 플레이 가능 범위와 세부 선택 흐름은 승인 전 제안이다.** H1 대 H1 AI는 이미 플레이할 수 있다. 이 문서는 최초 3명 목표를 구현할 때 기준 이미지 한 장을 완성 동작으로 오인하지 않도록 범위와 완료 조건을 정한다. 사용자 확인 전에는 B1/R3를 선택 가능한 완성 캐릭터로 표시하거나 새 전투 수치를 확정하지 않는다.

## 확정 기준과 현재 상태

| 항목 | 상태 | 기준 |
|---|---|---|
| 초기 캐릭터 | 확정 | H1 인간·B1 호랑이 비스트·R3 보라색 로봇, 플레이어가 캐릭터 선택 |
| 플랫폼·대전 | 확정 | PC 브라우저·키보드, 1인용 AI, 60초·2선승·동률/동시 KO 재경기 |
| 동작 제작 | 확정 | 기준 이미지 보존, 투명 PNG 포즈 교체, 공통 전투와 캐릭터 데이터 분리 |
| B1/R3 에셋 | 현재 | `reference.png` 각 한 장뿐. 대기·이동·공격·방어·피격·잡기·쓰러짐용 파생 포즈 없음 |
| 능력치·CPU 선택 | 기획 결정 필요 | 초기 동일 능력치와 선택 방식에 대해 사용자 확인 요청 중 |

[캐릭터 외형 기준](../design/characters.md)의 원본은 오른쪽을 보는 전신 자세다. 알파값 16 이상 기준의 관측 범위는 H1 x189~1120/y23~1184, B1 x141~1214/y21~1174, R3 x137~1109/y34~1258이다. 실제 PNG 크기는 H1/B1 1312×1199, R3 1214×1296이다. 이는 원본 크기·여백의 차이를 보여 주는 읽기 전용 측정이며, 게임용 발 기준점이나 피격 범위를 정한 수치는 아니다.

## 제안하는 플레이 흐름

1. 경기 시작 전에 H1/B1/R3의 이름과 기준 이미지가 있는 선택 화면을 연다. 아직 제작 중인 캐릭터는 검수 시안과 실제 선택 가능 상태를 구분한다.
2. 플레이어 캐릭터를 고른다. CPU 캐릭터를 누가 선택할지는 아래 결정 항목에 따른다. 선택을 확정할 때 두 캐릭터의 필수 동작 이미지와 정의를 확인하고 경기를 준비한다.
3. 경기 중 이름·체력·자세·그림·판정은 각 캐릭터를 따른다. 양쪽 모두 같은 공통 이동·전투·경기 함수를 사용한다. CPU는 공개 상태를 보고 해당 캐릭터의 정의에서 공격을 고른다.
4. 라운드 재경기·다음 라운드·경기 재시작은 같은 캐릭터 조합을 유지한다. 선택을 바꾸려면 명시적인 선택 화면 복귀를 사용한다. 복귀 시 진행 중인 경기·입력·오디오를 정리한다.
5. 마우스 클릭과 키보드 Tab/Enter/Space로 선택·시작·복귀를 조작한다. 전투 중인 WASD/U/I/J/K/Esc/R의 뜻은 유지한다. 선택 화면에 키보드만으로 도달하고 진행할 수 있어야 한다.

제안하는 진입점은 첫 화면의 **캐릭터 선택** 링크와 경기의 준비/결과 화면 **다시 고르기** 버튼이다. 진행 중에는 Esc로 정지한 뒤 그 버튼을 누르면 현재 경기를 버리고 선택 화면으로 이동한다. 이동할 때 눌린 전투키·콤보/잡기 입력·AI 판단·소리 재생을 정리하고 새 경기에는 선택한 조합만 전달한다. 키보드 포커스가 버튼에 있을 때 Enter/Space는 그 버튼만 작동하며 경기 전체 단축키를 중복 실행하지 않는다. 경기 영역에 포커스가 있을 때만 기존 Enter/Esc/R 단축키를 해석한다. 이 진입·복귀 흐름은 승인 전 제안이다.

### 제작 순서 제안

- **R0 · 기준 시안:** B1과 R3 원본을 보존한 채 각각 512×512 투명 캔버스·발 기준점(256,448) 후보로 비율 유지 정렬한다. 같은 1280×720 무대에서 H1과 함께 표시해 머리 높이·발 접지·꼬리/로봇 팔의 여백을 비교한다. 이 단계의 기준 이미지는 경기에서 공격하거나 움직이지 않는다.
- **R1 · B1 세로 검증:** B1의 이동·8공격·방어·피격·KO·잡기/풀기·메치기·점프 등 현재 경기에서 도달 가능한 모든 상태의 그림과 판정을 만든다. H1과 B1 양방향 대전을 검수한다.
- **R2 · R3 적용:** 같은 상태 범위를 R3에 적용하고 H1/B1/R3 조합을 검수한다. 두 캐릭터의 몸 비율·꼬리·장갑판 때문에 필요한 개별 판정과 표시 여유를 기록한다.
- **R3 · 선택 화면 공개:** 실제로 전투 가능한 세 명만 선택 가능하게 연결한다. 중간 시안은 별도 검수 화면에 두고, 게임 선택 화면에서 완성 상태처럼 표시하지 않는다.

### R0 실행 기준 · 2026-10-06 승인

사용자가 이 초안 확인 요청에 “좋아 계속 진행하자”라고 답했다. 우선 **R0 기준 시안 제작**에 대한 승인으로 기록한다. 능력치·CPU 선택 정책이나 R1~R3의 전체 게임 연결까지 승인된 것으로 해석하지 않는다.

- 원본의 모든 알파>0 픽셀 경계를 사용해 세로384px 안에 비율 유지 축소한다. 가로는 원본 캔버스 중점을 x256에 맞춘다. 축소 보간 후에는 희미한 원본 가장자리가 사라질 수 있으므로 결과 PNG에서 알파≥8의 발끝 바로 아래를 y448에 맞춘다. 전체 폭이512를 넘으면 시안을 중지하고 별도 배치안을 검토한다. 이는 H1 대기 그림의 알파 영역 y64~448과 비교하기 위한 **후보 정렬**이다.
- 원본 PNG는 그대로 두고 파생 PNG와 원본/결과 해시·실제 알파 범위·배율·오프셋을 각 캐릭터의 `derived/r0`에 기록한다. 픽셀을 새로 그리거나 특정 부위를 자르지 않는다. 리사이즈 보간으로 생기는 픽셀 변화와 원화의 창작 수정은 구분한다.
- 검수 페이지에서 H1의 현행 대기 그림과 B1/R3의 R0 후보를 같은 1280×720 무대·표시 배율0.625·지면y600·발 기준점으로 나란히 보여 준다. 키/충돌/AI에 연결하지 않는다.
- 512×512 RGBA, 투명 여백, 발끝 정렬, 가로 잘림 없음, 원본 SHA 불변과 실제 무대의 시각적 크기·외형을 확인한다. B1 꼬리와 R3 돌출 장갑의 시각적 폭은 피격 판정으로 해석하지 않는다. 사람의 외형·크기 승인 전에는 이 후보를 완성 동작으로 표시하지 않는다.

R0 정렬 후보와 나란히 보기 화면은 제작했다. 측정·브라우저 확인은 [R0 검수 기록](../reviews/roster-r0.md)에 남겼다. 2026-10-06 사용자가 **현재 R0 크기·외형 시안을 승인**했다. 이 승인으로 B1/R3의 정렬 기준은 정했지만 동작·판정·선택 가능 상태를 승인한 것은 아니다. R1에 들어가기 위한 [B1 상태→포즈 명세 초안](b1-pose-r1.md)을 작성했으며, 능력치·CPU 정책과 새 그림 제작 범위는 결정 전이다.

R1/R2의 신규 그림 수는 H1의 현재 145개를 기계적으로 복제해 확정하지 않는다. 대신 대기/걷기/앉기/점프·회전/공격8종의 준비·유효·회복/선·앉은 방어/피격/KO/잡기 시도·성공·실패·풀기·메치기·다운·복귀처럼 **도달 가능한 모든 상태**에 각 캐릭터 자신의 그림이 있어야 한다. 같은 그림을 의도적으로 재사용할 때는 연결 구간과 시각 품질을 명시한다. 새 원화·프롬프트·정렬 결과·탈락 후보는 버전별로 보존한다.

R1과 R2에 들어가기 전 해당 캐릭터의 **상태→포즈 목록**을 별도 명세로 작성한다. 각 항목은 원화 경로·512 캔버스의 발 기준점·표시 구간·허용 재사용 여부·좌우 반전·검수 상태를 포함한다. 기본/유효/회복·맞음/막음/KO·잡는 쪽/잡히는 쪽을 모두 열거하고 누락이 있으면 선택 가능 상태로 넘기지 않는다. 얼굴·색/무늬·체형·팔다리 구분·발 접지와 B1 꼬리/R3 장갑이 연속 그림에서 유지되는지 시안 비교로 확인한다.

## 전투·표시 설계 제안

- `CharacterDefinition`의 현재 체력·이동·피격·공격·콤보·잡기 자료를 각 캐릭터에 제공한다. 초기 능력치를 같게 할지 구분할지는 사용자 결정 후 이 문서에 수치로 기록한다. 공통 전투 함수에 캐릭터별 `if`를 늘리거나 H1용 공격 그림을 B1/R3에 입혀 출시하지 않는다.
- CPU의 현재 기본기 후보 순서·공중 대기 거리·잡기 접근/대기/풀기는 H1에서 검증한 정책이다. 초기 정의를 공유한다면 같은 정책으로 각 조합을 검증한다. 다른 수치를 선택한다면 공격 상한·피격 범위·잡기 거리·점프 대응을 해당 정의에서 다시 계산하고 대전 정책을 별도로 승인받는다. H1의 고정 거리 수치를 B1/R3에 그대로 적용했다고 해서 균형 검증 완료로 보고하지 않는다.
- 현재 `createMatch([player, cpu])`는 두 정의를 받을 수 있지만 화면의 `H1_ASSETS`, `H1_POSES`, `combatPose`, 오디오와 `H1Ai` 명칭/정책은 H1 기준이다. 선택 화면 구현 전에 필요한 부분만 캐릭터별 리소스·포즈와 공통 경기 연결로 나눈다. 기존 H1 동작과 전투 수치는 회귀 검증한다.
- 공격 판정과 피격 판정은 원본 알파 영역에서 자동 산출하지 않는다. B1 꼬리는 피격 범위에 자동 포함하지 않고, R3의 돌출 장갑도 기본 사각형을 무조건 키우지 않는다. 각 자세·공격의 접촉 그림과 사각형을 나란히 검수한다.
- 캐릭터가 달라져도 양쪽 실제 발 기준점과 카메라 좌표는 한 세계를 사용한다. H1용 현재 카메라 여유 192px가 새 포즈에도 맞는지 실제 알파 영역과 메치기/회전 중간각에서 재측정한다. 맞지 않으면 근거와 선택지를 먼저 제시한다.
- 효과음은 현행 9종이 H1용 시안이다. 다른 캐릭터에 임시 공유할지 별도 소리를 만들지는 음색 비교 후 결정한다. 선택 화면에서 음원이 준비되지 않아도 이미지/전투 오류와 구분한다.

## 확인받을 결정

1. **첫 대전 능력치:** B1/R3도 H1의 체력·이동·기본기·콤보·잡기 시간을 그대로 사용해 외형과 연결을 먼저 검증할지, 처음부터 각자 다른 수치를 정할지.
2. **CPU 캐릭터:** 플레이어가 양쪽을 각각 선택할지, 처음에는 플레이어만 선택하고 CPU는 H1으로 고정할지. 동일 캐릭터 대전을 허용할지도 함께 정한다. 선택 정책에 없는 조합은 화면에서 고를 수 없게 한다.
3. **제작 범위의 승인:** R0의 나란히 보기와 B1→R3 순서의 세로 검증을 채택할지. R1/R2의 모든 동작 제작은 각각 그림 시안 검수 후 연결한다.
4. **소리:** 초기에는 현행 효과음을 임시 공유하고 별도 청취 시안에서 캐릭터 차이를 정할지.

위 결정과 R0 시안 검수 뒤 세부 수치·캐릭터별 그림 목록·선택 화면 흐름을 확정한다. 이 초안은 게임 구현 승인으로 간주하지 않는다.
