# H1 효과음

2026-10-03 · S v0.1 · **상세 제안·사용자 확인 대기**. C/G 구현 뒤의 [전투 확장 §8](h1-combat-expansion.md)을 구체화한다. 현재 게임은 무음이며, 이 문서는 음원 제작·코드 연결·청취 검증 완료를 뜻하지 않는다. 기존 전투 수치·입력·CPU 선택은 유지한다.

## 확인할 범위와 제작 순서

**먼저 직접 합성한 효과음9종과 별도 청취 화면을 만드는 안이다.** 아래 재생 규칙을 연결 목표로 삼되, 청취 후 음색·길이·상대 음량·게임의 기본 소리 활성 여부와 초기 음량을 선택한 다음 전투 화면에 연결한다. 외부 게임 음원·음악·음성·발걸음·전용 KO/결과음은 이번 범위에 넣지 않는다.

| 단계 | 제안 산출물과 확인 시점 |
|---|---|
| S1 청취 시안 | WAV9개, 재현 가능한 합성 스크립트/제작 기록, 개별·조합 청취 화면. 이번 확인 후 제작할 범위 |
| S2 게임 연결 | 청취에서 선택한 음색/음량과 아래 사건 규칙을 표적·AI 경기 화면에 연결. S1 제작만으로 청취 선택까지 완료된 것으로 보지 않음 |

## 9종의 소리와 재생 사건

음색은 아래 방향의 **시안 제안**이며 최종 선택이 아니다. 선/앉은 기본기는 같은 슬롯 소리를 공유한다. 강공격은 단순히 음량만 키우지 않고 낮은 울림·질감으로 구분한다.

| 키 | 청취 시안 방향 | 게임에서의 재생 조건 |
|---|---|---|
| `hit-lp` 약손 | 짧고 가벼운 타격 | 약손의 실제 비방어 명중마다1회 |
| `hit-hp` 강손 | 두껍고 낮은 타격 | 강손의 실제 비방어 명중마다1회 |
| `hit-lk` 약발 | 손보다 넓게 퍼지는 타격 | 약발의 실제 비방어 명중마다1회 |
| `hit-hk` 강발 | 무게 있는 낮은 충격 | 강발의 실제 비방어 명중마다1회 |
| `guard` 방어 | 짧고 단단한 막힘 | 방어 사건마다1회. 같은 사건의 명중음은 없음 |
| `whiff` 헛침 | 짧은 공기 가르기 | 기본8공격이 유효 구간을 끝까지 지나고 접촉하지 않았을 때1회 |
| `grab-hold` 붙잡음 | 옷깃을 움켜쥐는 마찰 | 한 쌍 잡기 성립마다1회 |
| `grab-impact` 잡기 충격 | 붙잡음과 구분되는 밀치기 충격 | 성공H+18의 실제 피해 사건마다1회 |
| `grab-escape` 풀기 | 짧은 마찰과 분리 | 풀기 또는 동시 잡기 상쇄 한 쌍마다1회 |

- 헛침은 기본기 첫 회복F(`age === startup + active`)의 타격·잡기 해결 뒤 판단한다. 같은 공격ID가 유지되고 명중/방어 접촉 이력이 없을 때만 낸다. 그F까지 피격·잡기로 취소된 공격은 무음이다. 이미 낸 헛침음 뒤에 취소되면 추가 재생하지 않는다.
- **실패한 잡기 시도는 무음**으로 제안한다. 준비 단계의 휘두름음도 넣지 않는다. 유효 종료에 나는 헛침음이 늦게 느껴지는지는 S1 조합 및 S2 실제 플레이에서 확인한다.
- 붙잡음 뒤 풀기·시간 종료로 충격이 취소되면 잡기 충격음도 없다. 잡기 역할이 유지되는 동안 매F 재생하지 않는다. 여기서 잡기 중 행동 잠금은 오디오 차단 조건이 아니다.
- 마지막 KO/동시 KO/시간 종료 틱에 실제 발생한 명중·방어·헛침·붙잡음·충격·풀기도 위 규칙대로 소비한다. 결과 진입 뒤 신규 전투 사건은 만들지 않고, 방금 시작한 짧은 소리는 끝까지 들려준다. 별도 정지·초기화가 발생하면 즉시 중단한다.

## 제작·청취 제안

새 패키지 없이 합성 파형·필터·짧은 잡음을 조합해 PCM16·모노·48kHz WAV로 저장한다. 합성 설정과 난수 시드, 파일 해시·실측 길이·피크/RMS·시작/끝 페이드를 기록해 같은 시안을 재현한다. 이 규격은 이번 제작안이며 실제 파일은 아직 없다.

청취 화면은 버튼을 눌러 개별 소리, U→I→J, 동시 타격, 붙잡음→충격, 붙잡음→풀기를 들어보게 한다. 조합의 간격과 게임 사건 여부를 구분해 표시하고, 조합 청취를 실제 전투 성공 검사로 보고하지 않는다. 자동 재생은 하지 않으며 정지와 음량 조절을 제공한다. 청취 화면은 낮은 미리듣기 음량30%에서 시작하는 안이며 **게임 초기 음량 결정과 별개**다.

선택 기준은 손/발·약/강·명중/방어·붙잡음/충격/풀기의 구분, 반복해서 들었을 때의 피로, 시작/끝 클릭 잡음, 겹쳐 들릴 때의 왜곡이다. 개별 파형의 피크 검사만으로 실제 혼합 음량이나 청취 품질이 통과했다고 하지 않는다. 최종 길이·슬롯별 게인·마스터 기본값은 사용자가 시안을 들은 뒤 기록한다.

## 사건 소비와 중복 방지 설계

순수 전투는 소리를 직접 재생하지 않는다. 기존 `HitEvent`/`GrabEvent`를 재사용하고 헛침 결과 사건만 추가하는 안이다. 표적·경기 화면에서 공통 오디오 처리기로 전달한다.

1. 한 렌더에 최대5번 실행되는 **각 논리틱 직후** 사건을 읽는다. 갱신 전 실제 전투 진행 상태이며 `combat.frame`이 증가한 경우만 소비한다. 갱신 후 결과 단계라는 이유로 마지막 틱을 건너뛰지 않는다. 결과 화면에 보존된 마지막 사건도 반복 소비하지 않는다.
2. 새 전투마다 별도 세션ID를 만든다. 다음 라운드·동률 재경기·전체 초기화는 새 세션, 일시정지/재개는 같은 세션이다. 라운드 숫자만 중복 구분에 쓰지 않는다.
3. 기본기 키는 세션+공격자+공격ID+대상+종류다. 헛침은 대상 없는 공격 단위다. 잡기는 세션+소유 공격자+`grabId`+종류다. `grabId`는 전투 전체에서 유일하지 않으며 붙잡음/충격/풀기는 같은ID를 공유한다. 한 쌍 사건을 선수별 두 번 처리하지 않는다.
4. 같은 틱 동시 타격은 각 사건의 별도 재생 인스턴스를 사용한다. 앞 소리를 끊는 같은 객체 재사용을 피한다. 완료·실패·정지 모든 경로에서 화면 소유 인스턴스를 제거한다. 소비 기록은 활성 공격/잡기 및 최근 소비 틱 기준으로 정리해 긴 표적 검수에서도 계속 누적되지 않게 한다.
5. 오디오가 준비되지 않았거나 브라우저 오디오 잠금·음소거·음량0·해당 파일 누락 상태면 **소비하고 버린다**. 활성화 후 지난 사건을 다시 재생하지 않는다. 오디오 성공/실패와 비동기 완료가 전투의 시간·체력·입력·결과를 바꾸지 않는다.

## 활성화·정지·오류·지원 제안

PC Chrome·Edge의 **Web Audio 재생을 우선 지원·검증**하는 안이다. Web Audio를 사용할 수 없으면 안내와 함께 무음으로 플레이한다. HTML5 대체 재생까지 보장하는 범위는 별도 검수 전에는 포함하지 않는다.

| 상황 | 제안 동작 |
|---|---|
| 시작/계속하기/소리 켜기 | 실제 사용자 동작에서 활성화 요청. 관리자 잠금 해제와 실제 오디오 상태가 실행 중인지 확인한 뒤 활성 표시 |
| 활성화 지연/실패 | 재생 대기를 쌓지 않고 무음 진행·안내. 늦게 완료된 요청도 현재 세션·정지·음소거 상태를 다시 확인 |
| 일시정지·포커스 이탈 | 재생 중 소리와 청취 조합 예약을 중단·폐기하고 인스턴스 제거. 탭 복귀만으로 지난 소리나 전투를 재개하지 않음 |
| 다음 라운드·재경기·전체 초기화 | 이전 소리/예약/소비 기록 제거 후 새 세션. 사용자 소리 설정은 유지 |
| 소리 끄기/음량0 | 즉시 진행 소리 제거, 이후 사건 폐기. 다시 켜거나 음량을 올려도 밀린 소리 없음 |
| 일부 음원 누락/디코딩 실패 | 해당 소리만 생략·안내. 필수 이미지 실패와 분리하고 준비된 이미지로 무음 시작 가능 |
| 음원 준비가 늦음 | 이미지 준비와 독립적으로 경기 시작 허용. 이후 준비된 음원은 다음 신규 사건부터 사용 |

소리 켜기/끄기와0~100% 슬라이더를 두 화면에 제공한다. 슬라이더0은 음량에 의한 무음으로 표시하며 켜기 설정과 구분한다. 해당 페이지를 유지하는 동안 정지·라운드·경기 재시작에도 설정을 보존하고 새로고침은 청취 후 정할 초기값을 적용한다. 두 페이지 간 설정 공유/영구 저장은 추가하지 않는다. UI 조작은 전투를 자동 재개하지 않으며 전투키가 함께 전달되지 않게 한다.

로딩 오류 분기뿐 아니라 완료 후 오디오 캐시 존재 여부도 확인한다. `stopAll()` 호출만으로 임시 객체가 정리됐다고 보지 않는다. Phaser의 전역 오디오 관리자와 포커스 자동 재개, 잠금 대기 큐 때문에 화면이 소유한 소리의 중단·파기·실제 활성 상태를 명시적으로 관리한다.

## 검토 근거와 현재 상태

`main/174ad60`의 공통 전투 사건, 고정60Hz/렌더당 최대5틱, 경기 마지막 사건 보존, 표적/경기 로딩 및 설치된 Phaser4.2.1 소스의 완료·중단·언락·HTML5 대기 큐를 읽고 독립 검토했다. 새 음원·오디오 코드·오디오 테스트·실제 청취는 아직 없다. G의 자동162개 검사 결과를 S 검증으로 전용하지 않는다.

Phaser는 전역 오디오 관리자를 사용하고 Web Audio/HTML5 경로의 동작이 다르다. 실제 브라우저 사용자 동작과 활성 상태 확인이 필요하다. 참고: [Phaser 공식 오디오](https://docs.phaser.io/phaser/concepts/audio), [Chrome 자동재생 정책](https://developer.chrome.com/blog/autoplay/), [AudioContext.resume](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume). 설치된 구현과 공식 문서는2026-10-03에 확인했다.

G 근접 실제 플레이의 남은 제약은 [G 검수 기록](../reviews/h1-grab.md)을 따른다. 효과음 추가를 이유로 키 입력·거리·전투 시계를 바꾸지 않는다.
