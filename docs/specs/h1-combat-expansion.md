# H1 전투 확장 v0.2 · C/G 승인 / S 검토 초안

2026-10-03 승인 반영. **C 콤보에 이어 [잡기와 풀기 명세](h1-grab.md)의 G1~G4도 사용자 승인됐다.** C/G 코드와 화면·포즈 연결을 구현했고 G 자동·타입/빌드·에셋 검사를 통과했다. 실제 확인 범위는 [G 검수 기록](../reviews/h1-grab.md)을 따른다. S 효과음과 CPU의 새 기술 선택은 계속 승인 대기다. 최신 기준은 아래 §6~9와 G 상세 명세이며 §1~5는2026-10-01 방향 초안의 배경으로 보존한다. 과거 C/G의 승인 대기·제안 표기는 이번 승인으로 대체하며 구현을 검증 완료로 간주하지 않는다.

| 확인 | 승인 상태와 범위 |
|---|---|
| C 콤보 · 승인 | 선 U→I→J 한 경로, 비방어 명중 시 회복 취소. 기존 피해·밀려남·사거리 유지, 가까이서3타 |
| G 잡기 · 승인 | U+I의3F 판독, 선 자세 지상 잡기, 거리96 이하·피해18·풀기12F와 아래 시간표. G1~G4의 입력·동작·CPU 계약 적용 |
| S 효과음 · 대기 | 직접 합성 WAV9종 시안과 사건별 재생·음량/음소거. 최종 음색·초기 음량은 청취 후 선택 |
| CPU 범위 | C/G는 공통 규칙과 PLAYER 조작에 적용한다. CPU는 기존 기본기 전략·12F 판단을 유지하고 잡기 잠금에 대응한다. 콤보·잡기·풀기 선택 전략은 별도 확인 |

C/G/S는 각각 확인한다. C 단계에는 없었던 최대3F 손 대기를 G 승인으로 추가했다. 실제 겹친 U+I는 잡기이며 단독 손은 먼저 놓으면 즉시 시작한다. C의 나이는 실제 공격 시작부터 세고 후속 I/J는 손 대기 없이 기존 창을 사용한다. CPU가 새 잡기를 쓰기 전에는 PLAYER의 앉은 방어 유지 한계가 남는다.

2026-10-01. **경기 진행 명세의 추가 요구사항. 전투 확장 구현 전 사용자 확인이 필요하다.** 이 문서는 방향과 검증 기준을 정리하며, 아래 미정 수치가 남아 있는 상태로 구현하지 않는다. [경기 진행 v0.2](h1-match-flow.md)는2026-10-02 별도로 승인되어 먼저 구현한다. 이 승인은 아래 콤보·잡기·소리의 미정 수치에 적용되지 않는다.

## 1. 모션 재검수와 보완 방향

[검수 기록](../reviews/h1-motion-followup.md)과 [비교 도구](../reviews/evidence/h1-motion-comparison.html)를 사용한다. 비교 도구는 이전/현재 그림을 같은 시간·크기로 재생하고1F씩 이동한다. 실제 전투 코드는 변경하지 않는다.

- 걷기: 발 모으기→디디기→체중 이동→반대발 연결을 보완한다. 단순히 그림 수를 늘리는 것만으로 완료하지 않는다. 특히0→3→6→9F의 보폭 분배를 다시 확인한다.
- 약손: 팔 뻗기/회수 중간 자세와 발 고정을 확인하고, 다음 공격으로 넘어갈 때 팔·어깨·골반이 갑자기 바뀌지 않도록 연결 포즈를 검수한다.
- 콤보의 강손·발차기와 잡기는 별도의 연결/동작 이미지가 필요하다. 기존3포즈를 빠르게 교체하는 것만으로 자연스러움을 완료 처리하지 않는다.
- 지면 루트·동일 배율·원본 보존은 유지한다. 중간 그림 생성·정렬은 기존 승인 방식으로 수행하되 이번에는 검수와 초안 작성만 한다.
- 화면에서 한쪽씩 움직일 때의 발 미끄러짐, 좌우 반전, 중립→걷기→정지, 타격→피격/취소/KO 전환도 후속 플레이 검수에 포함한다.

## 2. 정해진2~3타 연계 후보

첫 후보는 **U → I → J = 약손 → 강손 → 약발**이다. U→I까지만 입력하면2타, J까지 이어 누르면3타를 시도한다. 자동으로3타가 나가거나 키를 계속 누르는 것만으로 반복되지는 않는다. 이 구체적인 키 순서와 아래 규칙은 사용자 승인 전 제안이다.

- 첫 단계는 선 자세·지상 연계1개만 대상으로 한다. 앉은/공중 콤보와 자유 캔슬은 이후 검토한다.
- 제안: 직전 타격이 실제 명중한 경우에만 지정된 후속 입력으로 회복을 끊고 다음 공격의 준비 동작을 시작한다. 헛치기·방어 성공 시에는 연계를 허용하지 않는다.
- 입력 허용 구간에1개의 다음 공격을 저장할 수 있게 한다. 범위 밖 입력·잘못된 키·피격 중 입력은 버린다. 기존 v0.3의 “공격 중 입력 예약 없음”에 대한 **지정 연계만의 예외**이며 전체 입력 버퍼 허용으로 확장하지 않는다.
- 공격마다 별도ID/타격 이력을 유지하여 각 타격은1회 피해만 준다. 3타 이후 다시 첫 타로 캔슬할 수 없으며 정상 회복을 거쳐야 한다.
- 실제 콤보는 상대의 피격 경직이 끝나기 전에 후속타가 맞는 경우다. 단순히 공격을 순서대로 실행했다는 이유로 콤보 성공으로 세지 않는다.
- 기존 피해8+12+10은 전부 명중하면 합계30이다. 이는 **기존 수치의 합산**이며 새 콤보 피해량 승인 또는 명중 보장이 아니다. 피해 보정 여부는 밸런스 검토 후 확정한다.
- 기존 밀려남24+36 때문에 먼 거리에서 시작하면 세 번째 공격이 닿지 않을 수 있다. 범위를 무시한 자동 명중·순간이동은 넣지 않는다. 유효 시작 거리, 전진 연결 동작 또는 연계 전용 밀려남을 비교해 명세화한다.
- 최초 J 후보 선정 당시 강발K의 준비24F는 강손 피격 경직20F보다 길었다. 2026-10-02 [첫 발차기 타격 수정](h1-heavy-kick-contact.md)으로 K 준비는12F가 됐지만 U→I→K는 여전히 미승인이다. 입력/캔슬 창·거리·밀려남 검증 없이 확정3타 콤보로 간주하지 않는다.

구현 전 확정할 항목: 입력 허용/보관F, 캔슬 가능한 첫/마지막F, 새 공격 시작 기준, 밀려남과 연계 가능 거리, 피해 보정 유무, 입력 불일치 처리, 피격/정지/경기 종료 시 연계 초기화.

## 3. U+I 잡기 후보와 입력 충돌

사용자가 잡기 키를 U+I로 선택했다. 기존에는 같은 갱신에 두 손을 누르면 강손 우선이므로 이 우선순위의 변경이 필요하다.

- 제안: 지상·선 자세·행동 가능한 상태에서 가까운 상대에게 잡기를 시도한다. 상대가 지상에 있어야 하며 선/앉은 자세 모두 대상이 될 수 있다. 뒤 방향 방어로는 막지 못한다.
- 피격/방어 경직 중인 상대를 바로 잡는 연계는 첫 단계에서 제외하여 타격→잡기 강제 반복을 막는다. 공중 잡기·뒤잡기·방향 교대·공중 던지기는 제외 제안이다.
- 잡기 시도→성공/헛잡기→풀기 허용→피해 확정→복귀로 구분한다. 기존 체력0 쓰러짐을 살아 있는 상대의 잡기 동작으로 재사용하지 않는다. 살아 있는 잡기 대상의 복귀 상태/모션을 별도로 정한다.
- 잡기 피해는 풀기 허용 시간이 끝나고 정해진 충격 시점에1회만 적용하는 안을 제안한다. 그 전에는 피해 없음. 풀렸다면 양쪽 피해0, 서로 겹치지 않게 분리 후 복귀한다.
- **풀기 제안:** 잡힌 쪽도 새 U+I 입력으로 푼다. 사용자는 잡기 입력만 선택했으므로 잡기 풀기 채택은 아직 확정하지 않았다.
- 동시 잡기는 서로 풀린 결과(피해0)로 처리하는 안을 제안한다. 타격과 잡기가 같은F에 성립할 때의 우선순위도 구현 전에 정한다.
- 잡기 중 시간 종료/KO/정지/초기화가 발생해도 두 선수의 잠금이 남지 않아야 한다. 마지막F의 잡기 피해를 먼저 반영한 뒤 기존 KO 우선 규칙으로 판정한다. 피해 확정 전 시간 종료라면 아직 받지 않은 잡기 피해를 추가하지 않는다.

### 약손→강손과 U+I를 구분하는 제안

“동시”를 실제로 같은 순간으로만 제한하면 누르기 어렵다. 후보는 두 키가 **3F(약50ms) 이내에 눌리고 서로 겹쳐 유지될 때** 잡기 입력으로 인정하는 방식이다. 이는 미확정 조정값이다.

먼저 들어온 손 공격을 즉시 실행하면 이미 시작한 주먹을 잡기로 되돌려야 한다. 반대로3F 기다리면 단독 손 입력에 최대50ms 지연이 생긴다. 따라서 **입력 지연을 포함한 비교 검수 후 채택**한다. 숫자만 임의로 확정하지 않는다.

- 잡기가 인정되면 그 입력의 약손·강손은 동시에 실행하지 않는다. U를 오래 유지하다 뒤늦게 I를 누르는 것은 잡기가 아니다.
- 공격 중에는 잡기를 예약하지 않는다. U→I 연계와의 구분, 유효하지 않은 잡기 조합을 강손으로 되돌릴지 여부도 세부 입력 명세에 포함한다.
- 키 입력 인식·물리 공격 준비F·애니메이션 시간은 분리한다. 단독 손 입력 지연을 기존 준비6/10F에 숨겨 “수치 유지”라고 보고하지 않는다.

구현 전 확정할 항목: 잡기 거리/준비/유효/헛잡기 회복F, 풀기 가능F·키, 성공 후 양쪽 행동 잠금·피해·밀려남·복귀/잡기 재시도 가능 시점, 동시 타격 우선순위, 동시 입력 허용F.

## 4. 타격 효과음 제안

Phaser는 효과음 재생·음량·음소거를 지원하며 사용자 동작 이후 오디오를 시작해야 하는 브라우저 제한을 고려해야 한다. [공식 오디오 문서](https://docs.phaser.io/phaser/concepts/audio)를 확인했다. 실제 프로젝트에서 소리를 생성·재생해 청취 검증한 상태는 아니다.

| 사건 | 후보 소리 | 재생 기준 |
|---|---|---|
| 약손/강손 명중 | 짧고 가벼운 타격 / 낮고 무거운 타격 | 실제 비방어 피해 이벤트1회 |
| 약발/강발 명중 | 발차기 충격 / 더 무거운 충격 | 실제 비방어 피해 이벤트1회 |
| 앉은 공격 명중 | 같은 공격 슬롯의 소리 재사용부터 | 일반/하단 판정과 소리의 재생 조건 분리 |
| 방어 | 막히는 소리 | 방어 이벤트1회, 명중음 대신 재생 |
| 헛치기 | 짧은 휘두름 | 유효 구간 종료까지 접촉이 없었던 공격1회 |
| 잡기 성공 | 짧은 붙잡음, 이후 충격음 | 상태 진입1회/실제 잡기 피해1회 |
| 잡기 풀기 | 풀리는 소리 | 풀기 결과1회, 잡기 충격음 없음 |

- 후보 스타일은 만화풍의 짧고 선명한 효과음이다. 먼저 직접 합성한 임시 WAV 시안을 들어보고 선택하는 안을 제안한다. 외부 게임 소리를 가져오지 않는다. 최종 음색·제작 방식은 확인 후 결정한다.
- 재생은 포즈 변경이 아닌 고유 공격ID/사건에 연결한다. 같은 공격에서5F 갱신되어도5번 울리지 않는다. 동시 타격은 서로 다른 두 사건으로 처리한다.
- 시작 버튼/사용자 키 동작에서 오디오 활성화를 시도한다. 소리 켜기/끄기·음량 조절을 제공하는 안이며 초기 음량은 청취 후 정한다.
- 탭 이탈·정지·초기화 때 잔여 소리를 멈추고, 재개할 때 지난 타격음을 몰아서 재생하지 않는다. 경기 종료를 만든 마지막 명중음은1회 허용하되 종료 후 새 전투음은 발생하지 않는다.
- 음원 누락/재생 차단 시 안내하고 무음으로 전투 검수는 계속할 수 있도록 한다. 오디오 로딩 실패와 필수 캐릭터 이미지 누락을 구분한다.
- BGM·음성·KO 아나운서는 이번 타격 효과음 제안에 포함하지 않는다. 명중 정지(히트스톱)·흔들림·파티클은 별도 제안 없이 임의 추가하지 않는다.

## 5. 변경 영향과 검증 계획

| 대상 | 필요한 변경·검증 |
|---|---|
| 기존 전투 명세 | 공격 중 입력 폐기·강손 우선·새 잡기 상태에 대한 승인된 예외 명시 |

## 6. 최신 플레이 근거와 C 콤보 승인 명세

### 플레이 근거

기존93개 자동 검사를 이번 작업에서 재실행했다. 무입력 PLAYER에게 CPU가2승하고 아래+뒤 지속 입력은60초 동안100:100 동률이 되는 검사가 통과했다. 방어 피해0, 선 강발의 앉은 상대 비접촉 때문에 앉은 방어 유지 문제는 CPU 판단만 바꿔 해결되지 않는다.

이번 내장 브라우저에서는 빌드 화면의 실제 키로 PLAYER가2:1 승리했다. 첫 라운드 J 반복으로54:0 승리, 둘째는0:90 패배, 셋째 D+J 반복으로40:0 승리였다. 이는 입력 펄스 플레이 결과이며 사람의 반응 난이도를 대표하지 않는다. S+A의 짧은 반복 입력에서는 지속 방어·피해0을 확인하지 못했다. [AI 검수 기록](../reviews/h1-ai-match.md)에 실제 수치와 초기 개발 화면의 프레임 진행 한계를 구분한다. 지속 방어와 모션/난이도의 최종 체감은 사용자 검수가 남는다.

다음 사람 검수는 중앙/양쪽 끝의 선 뒤 유지와 아래+뒤 유지, 방어 후 약손/약발 반격, 후진 추격, 경기 완주를 비교한다. 입력·거리·체력·시간·성공/실패를 기록한다. 새 잡기는 방어를 깨는 선택지가 될 수 있지만 CPU가 이를 쓰지 않는 단계에서는 방어 유지 문제를 해결했다고 보고하지 않는다.

### 연계 경로와 입력

이 절의 C 규칙은 **2026-10-03 사용자 승인 기준**이다. 선 자세 지상 U→I→J 한 경로만 허용한다. 단독 I에서 I→J로 진입하지 않으며 K·앉은/공중 공격·자유 캔슬은 제외한다. 후속타는 선 자세와 기존 방향을 유지하고 방향/S로 취소되지 않는다. 정상 회복 후 현재 방향/S를 다시 적용한다. CPU는 기존 AI v0.1을 유지해 공격 중 후속 입력을 내지 않는다. 공통 규칙이 양쪽에 같다는 이유로 CPU의 새 콤보 선택을 추가하지 않는다.

F는60Hz 논리 갱신이다. 공격 시작은age0, 기존 공격 나이를 증가시킨 뒤 취소를 판독한다. 새 후속 공격은그 갱신에age0이며 다시 증가시키지 않는다. 명중 갱신 자체에서 즉시 후속타로 바꾸지 않는다.

| 연결 | 다음 키 입력 허용 age(양 끝 포함) | 후속 시작 허용 age(양 끝 포함) |
|---|---|---|
| 선 U→선 I | U age3~12의 새 I | U age9~12, I 준비10F |
| 연계 선 I→선 J | I age5~22의 새 J | I age13~22, J 준비8F |

- 준비/유효 중 지정키1개를 저장하고 비방어 명중과 첫 취소F가 모두 충족되면 실행한다. 마지막 허용F 입력도 그 갱신에 실행한다. 같은 지정키를 더 눌러도 횟수·만료를 늘리지 않는다.
- 창 밖 입력·잘못된 키·여러 공격키가 같은 갱신에 들어온 입력은 버린다. 잘못된 입력으로 기존 올바른 예약을 지우지는 않는다. 키 유지만으로 후속타가 나오지 않는다.
- 방어 접촉·유효 종료까지 무접촉·피격 취소에서는 예약/연계 자격을 버린다. 방어도 기록하는 기존 `hitTargets`만으로 명중 확인하지 않는다. 상호 타격으로 공격이 취소되면 연계도 취소한다.
- 각 타격은 새 공격ID·단타 이력을 쓰고 연계 단계만 이어간다. J→U 반복 취소는 없다. KO·시간 종료·라운드/경기 초기화에서 단계와 예약을 제거한다.
- 정지 때 진행 공격·단계·명중 자격은 보존하되 예약키를 비운다. 재개 후 창이 남았다면 새 입력으로만 연결한다.

### 거리·피해·경직 검산

피해 보정 없이 기존 U8+I12=20, +J10=30을 사용한다. 밀려남24/36/32와 기본 공격의 준비/유효/정상 회복·판정은 그대로다. 지정 회복 취소만 예외이며 자동 전진·순간이동·사거리 확대는 없다.

U 최초 명중age6에서age12에 I를 시작하면6+10=16F 뒤 후속 접촉으로 경직16의 마지막 차단F에 맞는다. I 최초 명중age10에서age22에 J를 시작하면12+8=20F다. 각 취소를1F 늦추면 상대가 행동 가능하므로 창을 넘기지 않는다. 늦은 유효F 명중이어도 취소창을 늘리지는 않는다.

`d`는 **첫 U 접촉 때** 두 발 기준점의 수평 거리다. 양쪽 지상·공격자 정지·중앙에서 밀려남이 경계에 제한되지 않는 조건이다. 사각형은 양수 면적으로 겹쳐야 한다.

| 결과 | 계산 | 성립 거리 |
|---|---|---|
| U 단타 | d < 104+36 | 72 ≤ d < 140 |
| U→I | d+24 < 124+36 | 72 ≤ d < 136 |
| U→I→J | d+24+36 < 134+36 | 72 ≤ d < 110 |

이미 코너에 붙은 상대는 밀려남이 제한돼 U가 맞는140 미만에서3타가 닿을 수 있다. 공중 피격·경계 접근·KO에서는3타를 보장하지 않는다. 실제 위치를 매 타격 검사한다.

2026-10-02 순수 전투 함수에 미래의 취소 상태를 실험적으로 주입해109/110·135/136·139/140 경계와 마지막 취소F/+1F를 검산했다. **당시 초안 수치의 검산이며 C 구현 완료 검증은 아니다.** 이번 C 구현에서 실제 키 예약·캔슬 모션을 검수한다. 기존 유효 그림을 끝까지 재생한 뒤 다음 준비 그림으로 연결하고, 손·골반·지지발이 튀면 연결 그림을 검토한다. 새 그림 수는 시각 검수 후 산정하며 기존75포즈/원화는 보존한다.

## 7. G 잡기 승인 명세

2026-10-03 G1~G4 사용자 승인으로 [H1 잡기와 풀기 명세](h1-grab.md)를 구현 기준으로 적용했다. 아래 수치를 유지하면서 손 이벤트 순서·W/S와 발 우선순위·CPU 입력 계약·독립 잠금·종료 포즈·밀치기 동작을 구체화했으며 겹치는 내용은 해당 상세 명세를 우선한다. 공통 입력/전투·화면·잡기19포즈를 연결해 런타임94포즈를 사용한다. 검증 결과는 별도 기록한다.

### 손 입력 판독

이하 G 규칙은 **승인된 구현 기준**이다. 행동 가능한 지상 선 자세에서 두 손의 새 누름 논리F 차이가3 이하이고 실제로 겹칠 때 잡기1회다. 같은F 안에서 조합 뒤 두 손을 놓아도 완성한 겹침을 보존한다. 첫 U가F0이면 I가F0/1/2/3에 들어올 수 있다. F3에서 두 번째 키를 먼저 확인한 뒤 조합이 없으면 단독 손을 실행한다. 먼저 놓으면 그 갱신에 단독 손으로 확정한다. 단독 손 추가 지연은 최대3F(50ms)이며 기존 준비6/10F와 별개다. 대기 중 방향 이동은 기존대로다.

- 오래 유지한 U에4F 이후 I를 누르면 잡기가 아니다. 이미 시작한 주먹을 되돌리지 않는다. 공격 중에는 잡기/손 지연 판독을 끄고 C 지정 연계만 받는다.
- 같은 갱신 또는3F 대기 중 완성된 유효 U+I 조합은 J/K보다 우선해 모든 공격키를 소비한다. 따라서 F0 U → F1 I+K도 잡기다. 조합이 완성되지 않은 채 한 손 대기 중 J/K만 추가되면 대기 중 손과 새 발을 기존 K>I>J>U 순으로 선택하고 대기를 취소한다. 그 외 다중 입력은 기존 우선순위다.
- 손 대기 중 W/S로 점프/앉기 자격 전환이 발생하면 손 대기를 버리고 방향 입력을 처리한다. 처음부터 앉은 단독 손에는 지연이 없다. 앉은 상태의 같은 갱신 U+I는 실패 조합으로 소비하고 서로 다른F 손 입력을 잡기로 예약하지 않는다.
- 공중·피격·방어 경직·잡기 잠금에서는 새 공격 예약이 없다. 잡힌 쪽의 풀기만 예외다. 조합이 인정된 뒤 거리/대상 자격이 맞지 않아도 강손으로 되돌리지 않고 헛잡기를 끝낸다.
- OS 반복과 유지로 재시도하지 않는다. 정지/전환/초기화에서 판독 대기를 비우고 키를 놓은 뒤 새로 눌러야 한다.

### 동시 사건·정지·CPU

1. 일반 타격 접촉을 기존 양쪽 스냅샷 규칙으로 먼저 적용한다. 해당F에 일반 접촉이 있으면 새 잡기는 성립하지 않는다. 잡기 시도자는 방어할 수 없어 닿는 타격에 취소된다.
2. 일반 접촉이 없고 양쪽 잡기가 동시에 성립하면 피해0 상쇄, 풀기와 같은 분리/복귀를한 번 적용한다. 선수 배열 순서로 승자를 정하지 않는다.
3. 한쪽만 성공하면 양쪽을 함께 잠근다. 잠금 중 새 공격/잡기가 없으며, 대상은H+30부터 반격할 수 있다. 피격·방어 경직에 이어 확정 잡기를 허용하지 않는다.
4. 정지 시 양쪽 나이/잠금은 보존하고 입력 대기를 비운다. 재개 후 남은 창에 새 U+I만 받는다. 마지막 경기F의 충격을 먼저 반영한 뒤 KO/시간 우선순위를 적용한다. 충격 전 시간 종료면 예정 피해는 없다.
5. 종료·라운드 전환·초기화에서 양쪽 잠금/예약/손 판독을 함께 정리한다. 소유자만 지워 상대가 영구 잠기지 않게 한다.

공통 규칙은 양쪽 대칭으로 자동 검증한다. 새 잠금 상태에서 CPU는 입력을 내지 않고 해제 후 원래12F 일정에서 판단한다. 콤보 예약/손 판독 대기는 공개 관찰에 넣지 않는다.

**1차 CPU는 콤보·잡기·풀기를 새로 선택하지 않는 것으로 승인됐다.** 기존 기본기 펄스는 같은F 누름→놓기 짧은 탭으로 공통 판독해 시작 시점을 유지한다. 따라서 PLAYER 잡기는 CPU가 풀지 못하는 피해18 선택지이고 PLAYER의 앉은 방어 유지 한계도 남는다. CPU 새 기술까지 원하는 경우 선택 빈도·잡기 접근·풀기 반응을 AI 후속 명세로 먼저 확인한다. 표적 화면의 일회 잡기·풀기는 검수용 공통 입력이며 출시 AI의 새 전략이 아니다.

## 8. S 효과음 상세 제안

2026-10-03 최신 상세 제안은 [S 효과음 v0.1](h1-sound.md)이다. 아래는 요약이며 헛침/종료/지원/로딩의 모호한 부분은 새 문서로 구체화한다. S1 청취 시안 제작 확인 → 음색/음량 선택 → S2 게임 연결 순서다. 아직 제작·구현 승인은 아니다.

직접 합성한 짧은 만화풍 WAV9종을 청취 시안으로 만드는 안이다. 손발4종·방어·헛치기·붙잡음·잡기 충격·풀기 각1종이다. 선/앉은 공격은 슬롯 소리를 공유한다. 음색·길이·슬롯별 음량·초기 마스터 음량/기본 활성 여부는 시안 청취 후 별도로 선택한다. 외부 게임 음원을 사용하지 않는다.

| 사건 | 최신 재생 제안 |
|---|---|
| 손발4종 | 실제 비방어 피해 사건당 해당 슬롯1회 |
| 방어 | 방어 사건1회. 같은 사건 명중음 없음 |
| 헛침 | 기본8공격의 첫 회복F, 명중/방어 접촉이 없고 같은F 타격/잡기에 취소되지 않았을 때1회. 실패 잡기는 무음 |
| 붙잡음 | 한 쌍 잡기 성립1회 |
| 잡기 충격 | H+18 실제 피해1회. 그 전 풀기/시간 종료면 없음 |
| 풀기/동시 잡기 | 한 쌍 결과1회. 선수마다 두 번 재생하지 않음 |

유효 종료 헛침음이 늦게 들리는지는 시안 검수 대상이다. 준비에 먼저 휘두름을 재생하는 변경은 별도 제안이다. 마지막 KO/동시 KO/시간 종료 틱의 실제 사건은 각1회 허용하고 결과 중 신규 전투음은 없다. 방금 시작한 짧은 소리는 완료하되 명시적 정지/초기화에는 즉시 중단한다.

- 포즈 변경 대신 각 논리틱 직후 사건을 소비한다. 한 렌더에 최대5틱이므로 렌더의 마지막 결과만 읽지 않는다. `combat.frame`이 바뀐 틱만 소비해 결과 화면에 보존된 마지막 사건 반복을 막는다.
- 중복 구분은 전투 세션+공격자+공격ID+대상+종류다. 동률 재경기는 같은 라운드 숫자여도 새 세션이다. 잡기는 세션+소유 공격자+잡기ID+종류로 한 쌍을 구분한다. 전환 때 소비 기록을 정리한다.
- 동시 피격은 별도 인스턴스로 각각 재생하고 서로 끊지 않는다. 재생 처리/실패가 전투 시간·체력·결과에 영향을 주지 않는다.
- 시작/계속하기/소리 켜기 같은 실제 사용자 동작에서 활성화를 시도하고 실제 오디오 상태를 확인한다. 차단/실패는 안내 후 무음 진행한다. 활성화 요청 호출만으로 성공 표시하지 않는다.
- 브라우저 오디오 잠금·음소거·음량0·누락 중 사건은 소비 후 폐기한다. 잡기 중 행동 잠금은 무음 조건이 아니다. 나중에 밀린 소리를 재생하지 않는다. 정지/포커스 이탈/다음 라운드/초기화·음소거 전환에서 진행 소리·예약·임시 인스턴스를 정리한다.
- UI는 소리 켜기/끄기와0~100% 음량. 현재 페이지 세션의 설정을 라운드/경기 재시작에 유지하고 새로고침 때 초기값으로 돌아간다. 조작 중 전투키 유입을 막고 기존 포커스 이탈 정지를 유지한다.
- 음원 누락은 해당 소리만 생략하고 안내한다. 필수 이미지와 독립적으로 로드해 무음 경기 시작을 허용한다. 기존 전체 `loaderror` 분기와 디코딩 후 캐시 검사가 필요하다. Chrome/Edge Web Audio 우선, 미지원은 무음 진행으로 제안한다.

새 패키지 없이 Phaser 오디오·작은 화면측 처리기/에셋 매핑을 우선한다. G 구현의 붙잡음/충격/풀기 사건을 재사용하고 현재 없는 헛침 사건은 S 승인 후 순수 전투 결과에 추가한다. [Phaser 공식 오디오](https://docs.phaser.io/phaser/concepts/audio), [Chrome 자동재생 정책](https://developer.chrome.com/blog/autoplay/), [AudioContext resume](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume)와 설치된Phaser4.2.1을 검토했다. unlock 요청은 활성화 완료 보장이 아니며 포커스 복귀 자동 재개/HTML5 잠금 큐가 지난 소리를 재생하지 않게 관리한다. **아직 음원 제작·실제 청취는 하지 않았다.**

## 9. 설계·완료 조건·진행 순서

현재 C/G 구현은 지정 예약·비방어 명중 자격·연계 단계에 순서 있는 손 판독·최대3F 대기·한 쌍 잡기·독립 복귀 잠금·잡기 사건·종료 포즈 보존을 더했다. 기존8공격 수치와 C 창은 유지하며 기존75포즈와 잡기19포즈를 사용한다. CPU 새 선택 전략은 추가하지 않는다. S 승인 시 오디오 로딩 분리와 사건 소비를 추가한다.

C01~C05·G01~G06과 관련 R01은 승인된 검증 기준이다. S01~S04는 계속 승인 대기이며 아래 표 자체가 통과 보고는 아니다.

[콤보 검수 기록](../reviews/h1-combo.md)에 당시 근거와 미확인 체감을 구분한다. 이후 G는 자동162개·타입/빌드·94포즈 검사를 통과했고 [G 검수 기록](../reviews/h1-grab.md)에 실제 결과와 근접 성공/풀기 미확인 범위를 정리했다. S는 [상세안](h1-sound.md) 확인 대기이며 음원 제작·오디오 검증은 아직 없다. 자동 검사로 모션/음색의 최종 품질 승인을 대신하지 않는다.
