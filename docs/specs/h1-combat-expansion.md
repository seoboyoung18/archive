# H1 전투 확장 v0.1 · 방향 검토 초안

2026-10-01. **경기 진행 명세의 추가 요구사항. 구현 전 사용자 확인이 필요하다.** 이 문서는 방향과 검증 기준을 정리하며, 아래 미정 수치가 남아 있는 상태로 구현하지 않는다. 기존 [경기 진행 초안](h1-match-flow.md)도 아직 승인 대기다.

## 확정·요청·제안 구분

| 항목 | 상태 | 내용 |
|---|---|---|
| 모션 재검수 | 사용자 요청 | 걷기·공격의 자연스러움을 비교하고 부족한 부분을 보고 |
| 콤보 방식 | 사용자 선택 | 정해진2~3타 연계부터. 약손·강손·발차기 연결 |
| 잡기 입력 | 사용자 선택 | **U+I 동시 입력**. E키는 적용하지 않음 |
| 잡기 풀기 | 제안 | 상대도 U+I로 풀 수 있게 함. 동시 잡기·풀기 시간 등은 확인 필요 |
| 효과음 | 가능 여부 검토 요청 | 공격별 소리를 제공할 수 있음. 음색·제작 방식·음량은 승인 전 |
| 구체적 콤보·수치 | 제안/미정 | 아래 연계 후보와 입력/판정 수치를 확정한 뒤 구현 |

## 1. 모션 재검수와 보완 방향

[검수 기록](../reviews/h1-motion-followup.md)과 [비교 도구](../reviews/evidence/h1-motion-comparison.html)를 사용한다. 비교 도구는 이전/현재 그림을 같은 시간·크기로 재생하고1F씩 이동한다. 실제 전투 코드는 변경하지 않는다.

- 걷기: 발 모으기→디디기→체중 이동→반대발 연결을 보완한다. 단순히 그림 수를 늘리는 것만으로 완료하지 않는다. 특히0→3→6→9F의 보폭 분배를 다시 확인한다.
- 약손: 팔 뻗기/회수 중간 자세와 발 고정을 확인하고, 다음 공격으로 넘어갈 때 팔·어깨·골반이 갑자기 바뀌지 않도록 연결 포즈를 검수한다.
- 콤보의 강손·발차기와 잡기는 별도의 연결/동작 이미지가 필요하다. 기존3포즈를 빠르게 교체하는 것만으로 자연스러움을 완료 처리하지 않는다.
- 지면 루트·동일 배율·원본 보존은 유지한다. 중간 그림 생성·정렬은 기존 승인 방식으로 수행하되 이번에는 검수와 초안 작성만 한다.
- 화면에서 한쪽씩 움직일 때의 발 미끄러짐, 좌우 반전, 중립→걷기→정지, 타격→피격/취소/KO 전환도 후속 플레이 검수에 포함한다.

## 2. 정해진2~3타 연계 후보

첫 후보는 **U → I → J = 약손 → 강손 → 약발**이다. U→I까지만 입력하면2타, J까지 이어 누르면3타를 시도한다. 자동으로3타가 나가거나 키를 계속 누르는 것만으로 반복되지는 않는다. 이 구체적인 키 순서와 아래 규칙은 사용자 승인 전 제안이다.

- 첫 단계는 선 자세·지상 연계1개만 대상으로 한다. 앉은/공중 콤보와 자유 캔슬은 이후 검토한다.
- 제안: 직전 타격이 실제 명중한 경우에만 지정된 후속 입력으로 회복을 끊고 다음 공격의 준비 동작을 시작한다. 헛치기·방어 성공 시에는 연계를 허용하지 않는다.
- 입력 허용 구간에1개의 다음 공격을 저장할 수 있게 한다. 범위 밖 입력·잘못된 키·피격 중 입력은 버린다. 기존 v0.3의 “공격 중 입력 예약 없음”에 대한 **지정 연계만의 예외**이며 전체 입력 버퍼 허용으로 확장하지 않는다.
- 공격마다 별도ID/타격 이력을 유지하여 각 타격은1회 피해만 준다. 3타 이후 다시 첫 타로 캔슬할 수 없으며 정상 회복을 거쳐야 한다.
- 실제 콤보는 상대의 피격 경직이 끝나기 전에 후속타가 맞는 경우다. 단순히 공격을 순서대로 실행했다는 이유로 콤보 성공으로 세지 않는다.
- 기존 피해8+12+10은 전부 명중하면 합계30이다. 이는 **기존 수치의 합산**이며 새 콤보 피해량 승인 또는 명중 보장이 아니다. 피해 보정 여부는 밸런스 검토 후 확정한다.
- 기존 밀려남24+36 때문에 먼 거리에서 시작하면 세 번째 공격이 닿지 않을 수 있다. 범위를 무시한 자동 명중·순간이동은 넣지 않는다. 유효 시작 거리, 전진 연결 동작 또는 연계 전용 밀려남을 비교해 명세화한다.
- 강발K는 준비24F로 강손의 피격 경직20F보다 길다. U→I→K를 그대로 “확정3타 콤보”라고 부르지 않는다. 우선 J를 후보로 정한 이유이며 실제 시간·거리 경계 테스트가 필요하다.

구현 전 확정할 항목: 입력 허용/보관F, 캔슬 가능한 첫/마지막F, 새 공격 시작 기준, 밀려남과 연계 가능 거리, 피해 보정 유무, 입력 불일치 처리, 피격/정지/경기 종료 시 연계 초기화.

## 3. U+I 잡기 후보와 입력 충돌

사용자가 잡기 키를 U+I로 선택했다. 기존에는 같은 갱신에 두 손을 누르면 강손 우선이므로 이 우선순위의 변경이 필요하다.

- 제안: 지상·선 자세·행동 가능한 상태에서 가까운 상대에게 잡기를 시도한다. 상대가 지상에 있어야 하며 선/앉은 자세 모두 대상이 될 수 있다. 뒤 방향 방어로는 막지 못한다.
- 피격/방어 경직 중인 상대를 바로 잡는 연계는 첫 단계에서 제외하여 타격→잡기 강제 반복을 막는다. 공중 잡기·뒤잡기·방향 교대·공중 던지기는 제외 제안이다.
- 잡기 시도→성공/헛잡기→풀기 허용→피해 확정→복귀로 구분한다. 기존 체력0 쓰러짐을 살아 있는 상대의 잡기 동작으로 재사용하지 않는다. 살아 있는 잡기 대상의 복귀 상태/모션을 별도로 정한다.
- 잡기 피해는 풀기 허용 시간이 끝나고 정해진 충격 시점에1회만 적용하는 안을 제안한다. 그 전에는 피해 없음. 풀렸다면 양쪽 피해0, 서로 겹치지 않게 분리 후 복귀한다.
- **풀기 제안:** 잡힌 쪽도 새 U+I 입력으로 푼다. 사용자는 잡기 입력만 선택했으므로 잡기 풀기 채택은 아직 확정하지 않았다.
- 동시 잡기는 서로 풀린 결과(피해0)로 처리하는 안을 제안한다. 타격과 잡기가 같은F에 성립할 때의 우선순위도 구현 전에 정한다.
- 잡기 중 시간 종료/KO/정지/초기화가 발생해도 두 선수의 잠금이 남지 않아야 한다. 마지막F의 잡기 피해를 먼저 반영한 뒤 기존 KO 우선 규칙으로 판정한다. 피해 확정 전 시간 종료라면 아직 받지 않은 잡기 피해를 추가하지 않는다.

### 약손→강손과 U+I를 구분하는 제안

“동시”를 실제로 같은 순간으로만 제한하면 누르기 어렵다. 후보는 두 키가 **3F(약50ms) 이내에 눌리고 서로 겹쳐 유지될 때** 잡기 입력으로 인정하는 방식이다. 이는 미확정 조정값이다.

먼저 들어온 손 공격을 즉시 실행하면 이미 시작한 주먹을 잡기로 되돌려야 한다. 반대로3F 기다리면 단독 손 입력에 최대50ms 지연이 생긴다. 따라서 **입력 지연을 포함한 비교 검수 후 채택**한다. 숫자만 임의로 확정하지 않는다.

- 잡기가 인정되면 그 입력의 약손·강손은 동시에 실행하지 않는다. U를 오래 유지하다 뒤늦게 I를 누르는 것은 잡기가 아니다.
- 공격 중에는 잡기를 예약하지 않는다. U→I 연계와의 구분, 유효하지 않은 잡기 조합을 강손으로 되돌릴지 여부도 세부 입력 명세에 포함한다.
- 키 입력 인식·물리 공격 준비F·애니메이션 시간은 분리한다. 단독 손 입력 지연을 기존 준비6/10F에 숨겨 “수치 유지”라고 보고하지 않는다.

구현 전 확정할 항목: 잡기 거리/준비/유효/헛잡기 회복F, 풀기 가능F·키, 성공 후 양쪽 행동 잠금·피해·밀려남·복귀/잡기 재시도 가능 시점, 동시 타격 우선순위, 동시 입력 허용F.

## 4. 타격 효과음 제안

Phaser는 효과음 재생·음량·음소거를 지원하며 사용자 동작 이후 오디오를 시작해야 하는 브라우저 제한을 고려해야 한다. [공식 오디오 문서](https://docs.phaser.io/phaser/concepts/audio)를 확인했다. 실제 프로젝트에서 소리를 생성·재생해 청취 검증한 상태는 아니다.

| 사건 | 후보 소리 | 재생 기준 |
|---|---|---|
| 약손/강손 명중 | 짧고 가벼운 타격 / 낮고 무거운 타격 | 실제 비방어 피해 이벤트1회 |
| 약발/강발 명중 | 발차기 충격 / 더 무거운 충격 | 실제 비방어 피해 이벤트1회 |
| 앉은 공격 명중 | 같은 공격 슬롯의 소리 재사용부터 | 일반/하단 판정과 소리의 재생 조건 분리 |
| 방어 | 막히는 소리 | 방어 이벤트1회, 명중음 대신 재생 |
| 헛치기 | 짧은 휘두름 | 유효 구간 종료까지 접촉이 없었던 공격1회 |
| 잡기 성공 | 짧은 붙잡음, 이후 충격음 | 상태 진입1회/실제 잡기 피해1회 |
| 잡기 풀기 | 풀리는 소리 | 풀기 결과1회, 잡기 충격음 없음 |

- 후보 스타일은 만화풍의 짧고 선명한 효과음이다. 먼저 직접 합성한 임시 WAV 시안을 들어보고 선택하는 안을 제안한다. 외부 게임 소리를 가져오지 않는다. 최종 음색·제작 방식은 확인 후 결정한다.
- 재생은 포즈 변경이 아닌 고유 공격ID/사건에 연결한다. 같은 공격에서5F 갱신되어도5번 울리지 않는다. 동시 타격은 서로 다른 두 사건으로 처리한다.
- 시작 버튼/사용자 키 동작에서 오디오 활성화를 시도한다. 소리 켜기/끄기·음량 조절을 제공하는 안이며 초기 음량은 청취 후 정한다.
- 탭 이탈·정지·초기화 때 잔여 소리를 멈추고, 재개할 때 지난 타격음을 몰아서 재생하지 않는다. 경기 종료를 만든 마지막 명중음은1회 허용하되 종료 후 새 전투음은 발생하지 않는다.
- 음원 누락/재생 차단 시 안내하고 무음으로 전투 검수는 계속할 수 있도록 한다. 오디오 로딩 실패와 필수 캐릭터 이미지 누락을 구분한다.
- BGM·음성·KO 아나운서는 이번 타격 효과음 제안에 포함하지 않는다. 명중 정지(히트스톱)·흔들림·파티클은 별도 제안 없이 임의 추가하지 않는다.

## 5. 변경 영향과 검증 계획

| 대상 | 필요한 변경·검증 |
|---|---|
| 기존 전투 명세 | 공격 중 입력 폐기·강손 우선·새 잡기 상태에 대한 승인된 예외 명시 |
| 입력 | U→I와 U+I 구별, 키 유지/OS 반복/놓기, 방향/공중/경직/정지와 충돌 없음 |
| 전투 데이터 | 허용된 연계 목록·캔슬/입력 창·잡기 규칙 분리. 캐릭터마다 공통 코드를 복제하지 않음 |
| 피해·방어 | 명중/방어/헛치기 분기, 연계각타1회 피해, 잡기 풀기 피해0, 무한 연계/타격→잡기 잠금 방지 |
| 거리·시간 | 가까움/최대 거리/코너/좌우 반전의2~3타, 입력 창 직전/첫F/마지막F/직후, 경직 중 진짜 연속 명중 여부 |
| 모션 | 캔슬 시 팔/발 연결, 잡는 쪽과 잡히는 쪽의 손 접촉, 성공/풀기/헛잡기/복귀 동작 검수 |
| 경기 | 마지막F 타격/잡기·동시 KO 우선, 정지 중 풀기 시간 보존, 결과 후 피해 없음, 다음 라운드 잠금/연계 초기화 |
| 효과음 | 공격8종의 슬롯별 소리·방어·헛치기·잡기/풀기, 중복/밀린 재생 없음, 음소거·볼륨·탭 복귀·실제 청취 |

위 항목은 계획이며 구현 검증 완료가 아니다. 순서는 모션 보완 대상 결정 → 연계/잡기/소리 제안 확인 → 수치·입력 충돌과 동작 제작 명세 확정 → 기능별 구현·회귀 검증으로 제안한다. 경기 진행 초안과의 구현 우선순위도 사용자에게 확인한다.
