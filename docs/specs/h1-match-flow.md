# H1 경기 진행 명세 v0.1 · 검토용 초안

작성일: 2026-10-01. **사용자 승인 대기. 이번 작업은 명세 작성까지이며 구현하지 않는다.**

## 1. 목적·승인 범위

H1의 한 경기를 시작 → 라운드 종료 → 다음 라운드/재경기 → 최종 승패 → 재시작까지 연결한다. 기존 [전투 v0.3](h1-combat-draft.md)의 확정 규칙을 구체화한다. 아래에서 **확정**은 기존 승인 내용, **제안**은 이번 승인 대상이다. 초안의 제안이 기존 승인 내용을 자동으로 대체하지 않는다.

| 구분 | 내용 |
|---|---|
| 기존 확정 | H1 대 H1, 체력100, 라운드60초, 먼저2승, 동률/동시 KO 재경기 |
| 기존 확정 | 마지막1F 타격까지 적용, KO가 시간 종료보다 우선, 승수는 종료당1회 반영 |
| 기존 확정 | 다음 라운드 Enter/버튼, 경기 결과 R/버튼 재시작, 정지·포커스 처리와 초기화 |
| 이번 제안 P1 | 별도 경기 검수 화면으로 연결. AI는 다음 단계이며 이번 상대는 입력 없는 표적 |
| 이번 제안 P2 | 추가 시작 카운트다운 없이 수동 시작. KO 쓰러짐18F가 끝나면 다음 행동 활성화, 시간 종료는 즉시 활성화 |
| 이번 제안 P3 | KO는 선택 A 이미지, 시간 종료는 `TIME UP`, 동시 KO는 `DOUBLE KO` 텍스트. 최종 승패는 별도 한국어 문구 |
| 이번 제안 P4 | 재경기도 Enter/버튼으로 수동 시작. 경기 결과의 R/버튼은 승수까지 지우고 첫 라운드 준비로 돌아감 |

P1~P4와 아래 세부 동작 전체를 확인받은 뒤 구현한다. 이 문서의 승인은 실제 동작·품질 검증 통과를 의미하지 않는다.

## 2. 현재 상태와 이번 구현 범위 제안

현재 `src/combat/combat.ts`는 공격·방어·동시 피해·체력0 종료를 처리하지만 시간·승수·경기 결과는 없다. `src/combat-preview.ts`는 입력 없는 CPU 표적과 검수용 방어 입력, 체력바·KO 이미지·초기화를 제공한다. `FixedStep`은60Hz, 렌더 갱신당 최대5F를 처리한다. H1 그림은48포즈이며 걷기·선 약손의 중간 그림을 반영했다.

- 포함: 경기 상태·시간·라운드 번호·양쪽 승수·라운드 및 최종 결과, 다음 라운드/재경기/전체 재시작, 일시정지·로딩 실패, 표시와 검증.
- P1 제안: `match.html`에 경기 검수 화면을 만든다. 기존 `combat.html`의 공격·방어 검수와 초기화 기능은 보존하고 서로 링크한다. 상대에는 `CPU / 표적 · AI 연결 전`을 표시한다. 새 화면에서 상대의 검수용 방어 선택은 제공하지 않는다.
- 이번 단계는 경기 진행 계층의 검증이다. AI 구현은 다음 단계이며 최종1인용 AI 대전 범위에서 제외하는 결정은 아니다. CPU 승리·동시 KO 등의 양방향 사례는 자동 테스트의 두 선수 입력/초기 상태로 검증한다.
- 제외: 새 공격·수치 변경·추가 포즈/그래픽 생성·음향·화면 흔들림·카메라 변경·B1/R3·캐릭터 선택·로컬2인. 기존 모션과 경계 쓰러짐 그림 잘림은 별도 보완 대상으로 남긴다.

## 3. 사용자 흐름과 경기 상태

P2/P4 제안의 구체화다. 상태와 데이터 명칭은 설계 설명이며 화면에 개발용 상태명을 노출하지 않는다.

| 상태 | 보여줄 내용 | 가능한 행동·전이 |
|---|---|---|
| 로딩 | 로딩 안내 | 준비 전에는 시작/전투 입력 불가 |
| 로딩 실패 | 실패 안내·다시 시도 | 에셋이 모두 정상일 때만 라운드 준비. 기존 페이지 재로딩 방식 사용 가능 |
| 라운드 준비 | ROUND 1, 체력100/100, 시간60, 승수0:0, 시작 버튼 | 게임 시작 버튼 또는 게임 영역의 새 Enter 입력으로 진행 |
| 라운드 진행 | 번호·체력·시간·승수와 조작 화면 | WASD/UIJK, 정지. 종료 조건이 생기면 해당 결과로1회 전이 |
| 라운드 결과 | 종료 이유·승자 또는 재경기 이유·갱신된 승수 | 새 Enter 또는 활성화된 다음 라운드/같은 라운드 재경기 버튼 |
| 경기 결과 | 최종 승자·최종 점수·마지막 종료 이유 | 활성화된 새 R 또는 경기 재시작 버튼 |
| 일시정지 | 일시정지 안내·계속 버튼, 원래 화면과 상태 보존 | 계속/Enter/Esc로 저장해둔 이전 상태 복귀 |

- P2: 첫 시작은 준비 화면에서 기다린다. `3·2·1` 또는 별도 `FIGHT` 카운트다운을 추가하지 않는다.
- 기존 확정인 다음 라운드 시작은 버튼/Enter1회로 초기화 후 바로 진행한다. 중간 준비 처리는 원자적으로 수행하고 두 번째 시작 입력을 요구하지 않는다.
- P4: 재경기도 같은 방식으로 수동 진행한다. 결과를 확인하기 전에 자동으로 초기화하지 않는다. 기존 v0.3의 “같은 라운드 준비로 돌아감”은 결과 확인 후 이 준비 처리를 거치는 것으로 구체화한다.
- 승리 라운드가 끝나도 결과 화면에서는 방금 끝난 번호를 유지한다. 다음 라운드를 실제 시작할 때만 번호를 증가시킨다. 번호 = 완료된 승패 결정 라운드 수 + 1이되, 경기 결과는 마지막 진행 번호를 유지한다.
- 먼저2승이면 라운드 결과 대신 경기 결과로 들어가며 다음 라운드 버튼은 없다. 2:0이면 ROUND 2 종료, 2:1이면 ROUND 3 종료다.
- P4: 경기 결과에서 R/재시작을 누르면 ROUND 1 준비·승수0:0으로 돌아간다. 다시 시작 버튼/Enter로 진행한다. 진행 중 R은 무시하며 이번 화면에 중도 경기 포기/재시작 기능은 추가하지 않는다.

## 4. 경기 시간과 종료 판정

다음 전투 시간·판정 순서는 기존 확정 규칙을 수치로 표현한 것이다. 정수 초 표시 방식은 이번 세부 제안이다.

- 라운드 시작 시 남은 시간3600F(60×60). 실제 처리한 전투 논리1F마다1을 줄인다. 화면의 정수 초는 `ceil(남은F / 60)`이며 3600~3541F는60, 3540F는59, 1F는1, 0F는0이다.
- 준비·결과·정지·로딩 중에는 라운드 시간을 소비하지 않는다. 결과의 KO 그림 재생 시간도 라운드 시간과 분리한다.
- 렌더 주사율과 관계없이 같은 논리 입력에서 결과가 같아야 한다. 기존 최대5F 처리/초과 지연 폐기 규칙을 유지한다. 과부하 때 벽시계60초와 달라질 수 있으며 별도 실시간 타이머로 보정하지 않는다.
- 진행 상태에서만 다음 순서를 한 번 수행한다: 두 선수 입력 → 공통 전투1F(이동·동시 타격·피해 포함) → 남은F 1감소 → 양쪽 HP 확인 → KO가 없고 남은F=0이면 체력 비교 → 결과 확정.

| 우선순위 | 종료 조건 | 결과·승수 |
|---|---|---|
| 1 | 같은 갱신 후 양쪽 HP0 | 동시 KO. 승수 불변, 같은 번호 재경기 |
| 2 | 한쪽만 HP0 | 생존 선수 라운드 승리, 해당 승수+1 |
| 3 | 양쪽 HP>0이고 시간0, 체력 차이 있음 | 높은 체력 쪽 라운드 승리, 해당 승수+1 |
| 4 | 양쪽 HP>0이고 시간0, 체력 동일 | 시간 종료 동률. 승수 불변, 같은 번호 재경기 |

- HP가100보다 낮아도 재경기는 양쪽100에서 시작한다. 동일 체력 재경기에는 낮은 체력을 이어받거나 연장전을 적용하지 않는다.
- 마지막 남은1F의 타격으로 두 선수 체력이 바뀌면 바뀐 체력으로 결과를 결정한다. 그 갱신에서 KO가 발생하면 시간도0이지만 종료 이유는 KO/동시 KO다.
- 종료 시 승수와 결과는 한 번만 저장한다. 결과/정지 상태에 다시 갱신 요청이나 같은 이벤트가 와도 승수가 늘지 않는다. 같은 렌더 내 남은 고정 갱신에서도 전투를 다시 처리하지 않는다.
- 끝난 이후 전투의 HP·위치·공격 나이·경직·결과·승수·라운드 시간은 고정한다. 양쪽 피해를 순서대로 승패 판단하여 한쪽 동시 타격을 누락하지 않는다.

## 5. 결과 표시·연출 제안 (P2/P3)

| 상황 | 중앙 표시 | 결과 설명·후속 행동 |
|---|---|---|
| 한쪽 KO, 아직2승 전 | 선택한 A `K O!!` 이미지 | `PLAYER 라운드 승리` 또는 `CPU 라운드 승리`, 점수, 다음 라운드 |
| 시간 종료, 체력 차이 있음 | `TIME UP` 텍스트 | 높은 체력 선수의 라운드 승리, 점수, 다음 라운드 |
| 시간 종료, 동일 체력 | `TIME UP` 텍스트 | `체력 동일 · 같은 라운드 재경기`, 점수 유지 |
| 동시 KO | `DOUBLE KO` 텍스트 | `동시 KO · 같은 라운드 재경기`, 점수 유지 |
| PLAYER가2승 | 마지막 이유에 따른 `K O!!` 또는 `TIME UP` | `승리!`, `PLAYER 경기 승리`, 최종 점수·경기 재시작 |
| CPU가2승 | 마지막 이유에 따른 `K O!!` 또는 `TIME UP` | `패배`, `CPU 경기 승리`, 최종 점수·경기 재시작 |

- `K O!!`는 한쪽 체력0일 때만 사용한다. 시간 종료 승리와 동시 KO에 A 이미지를 겹쳐 표시하지 않는다. 최종 승리라도 시간으로 이겼으면 `TIME UP`와 `승리!`를 함께 표시한다.
- A 이미지의 현재 위치(640,270)·가로640·비율 유지 기준을 재사용한다. 결과 설명/버튼은 별도 영역에 표시하여 이미지와 겹치지 않게 한다. 추가 글자는 텍스트로 구현하며 새로운 이미지 선택을 요구하지 않는다.
- 결과·승수는 종료 즉시 표시한다. KO/동시 KO는 쓰러짐3포즈×6F=18F가 모두 재생된 후에 다음 라운드/재경기/경기 재시작 버튼과 해당 단축키를 활성화한다. 기다리는 동안 `쓰러짐 연출 중`을 표시하고 일찍 누른 입력은 예약하지 않는다.
- 종료 틱에는 쓰러짐 나이0. 이후 일시정지되지 않은 결과 갱신에서만 연출 시간을 진행한다. 0~5/6~11/12~17F는 각각 포즈0/1/2이며 18F 이후 최종 포즈를 유지한다. 동시 KO는 두 선수 모두 같은 시간으로 재생한다.
- 승리 선수·시간 종료 선수는 종료 순간 포즈를 유지한다. 공중 KO 표시만 기존 방식대로 바닥에 맞추며 전투 좌표를 움직이지 않는다.
- 시간 종료는 쓰러짐 연출이 없으므로 후속 버튼을 즉시 활성화한다. 강제 결과 유지 시간이나 자동 다음 라운드는 없다.
- 타이머·양쪽 승수·라운드 번호는 읽을 수 있는 텍스트로 제공한다. 결과 변경은 접근성 상태 안내로 알리며 매 프레임 읽도록 만들지 않는다.

## 6. 입력·일시정지·전환

기존 입력 유지/해제·초기화 규칙을 따르고 결과 화면의 입력 우선순위를 구체화한다.

- 게임 영역에 포커스가 있고 라운드 진행 중일 때만 전투 키를 처리한다. UI 버튼의 Enter/Space와 라운드 단축키가 한 입력에서 중복 실행되지 않게 한다. 키 자동 반복으로 전환하지 않는다.
- 준비의 Enter=경기 시작, 진행의 Enter=동작 없음, 라운드 결과의 Enter=활성 후 다음 라운드/재경기, 경기 결과의 Enter=전역 단축키 없음(재시작 버튼에 포커스가 있으면 버튼 조작 가능).
- Esc 또는 게임/창 포커스 상실·탭 숨김으로 진행을 정지한다. 결과의 KO 연출 중에도 정지하여 연출 시간을 보존한다. 준비·로딩·실패 화면에서는 정지 상태를 추가하지 않는다.
- 결과에서 정지해도 결과·점수·그림은 보존한다. 정지 중에는 다음 라운드/재경기/R/재시작을 비활성화하고 명시적 재개를 먼저 요구한다. Enter는 재개만 하며 같은 입력으로 라운드까지 넘어가지 않는다.
- 포커스 복귀만으로 재개하지 않는다. 계속 버튼 또는 게임 영역의 새 Enter/Esc로 원래 진행/결과 상태를 복원한다. 결과 버튼을 조작하기 위한 화면 내부 포커스 이동은 KO 연출이 끝난 결과에 불필요한 재개 요구를 만들지 않는다.
- 로딩·정지·결과·전환에서 입력 기록과 누적 논리 시간을 비운다. 전환 중 누른 키나 계속 유지한 키는 놓았다가 다시 눌러야 한다. 버튼을 길게 누르거나 더블클릭해 다음 라운드를 건너뛰지 않는다.
- 다음 라운드/재경기 시작 버튼의 더블클릭은 첫 클릭 후 진행 상태에서 무시한다. 전체 재시작 버튼의 중복 이벤트는 준비 화면에서 무시한다. 단축키/버튼 처리는 상태 전이당1회다.

## 7. 초기화 계약

| 데이터 | 다음 라운드 | 같은 라운드 재경기 | 경기 전체 재시작 |
|---|---|---|---|
| 양쪽 승수 | 방금 반영된 점수 유지 | 그대로 유지 | 0:0 |
| 라운드 번호 | 이전 번호+1 | 이전 번호 유지 | 1 |
| 체력·시간 | 각각100·60초 | 각각100·60초 | 각각100·60초 |
| 위치·방향 | (400,600)/(880,600), 서로 마주봄 | 동일 | 동일 |
| 선수 상태 | 선 대기, 속도0, 지상 | 동일 | 동일 |
| 공격·경직·입력 | 공격/타격 이력/경직/보류 입력 제거, 공격ID 초기화 | 동일 | 동일 |
| 논리·표시 시간 | 전투 프레임·누적 시간·포즈 나이·KO 연출0 | 동일 | 동일 |
| 이전 결과·UI | 라운드/경기 결과와 종료 그래픽·타격 기록 제거 | 동일 | 동일 |
| 다음 상태 | 라운드 진행 | 라운드 진행 | 라운드 준비 |

위 표의 마지막 행 '라운드 준비'는 수동 시작을 기다리는 상태다. H1 정의·선택 에셋과 이미 로딩한 리소스는 유지하고 페이지를 새로고침하지 않는다. 입력의 차단 목록은 단순히 지워서 유지 중인 키를 재활성화하지 않는다. AI 연결 이후에는 이 전환에 AI 판단 주기/유지 명령 초기화도 포함하며, 이번에는 사용하지 않는 AI 구조를 미리 만들지 않는다.

## 8. 설계·영향 범위 제안

- `src/combat/match.ts`(신규 후보): 공통 전투 상태를 감싸 경기 단계·승수·남은F·결과·라운드 전환을 관리하는 순수 로직. 캐릭터별 전투 함수를 복제하지 않는다. 두 선수의 공통 입력을 받아 후속 AI 연결이 가능하게 한다.
- 결과 이유는 `ko / double-ko / timeout / timeout-tie`, 승자는 선수ID 또는 없음으로 보관한다. 라운드 번호·승수·종료 이유는 경기 상태에서 읽고 화면이 별도로 계산하지 않는다. 최종 승자는 승수2에서 도출한다.
- `CombatState.ended`는 기존 체력0 종료 의미를 유지한다. 시간 종료는 경기 계층이 전투 호출을 중단한다. UI는 경기 단계/결과를 기준으로 제어하여 `ended=false`인 시간 종료에 전투를 재개하지 않는다.
- 일시정지는 복귀할 이전 상태를 보존한다. 결과 연출 시간은 전투 프레임과 분리하되 정지·초기화는 같은 경기 전환 계약을 따른다.
- `match.html`와 화면 연결 모듈(신규 후보): 현재 Phaser 표시·H1 포즈·A 이미지·입력·고정 갱신을 재사용한다. 실제 코드 분리 위치는 승인 후 설계에서 정하되 전투 판정 복제나 새 패키지 도입은 하지 않는다.
- 기존 전투 검수의 방어 선택·초기화는 해당 화면에만 남긴다. 경기 화면은 이 문서의 결과 및 재시작 의미를 사용한다.

## 9. 정합성 검토와 완료 조건

문서 검토: 전투 v0.3 §2/4/6/8의 시간·종료·초기화, 애니메이션의 KO18F·승자 정지, 현재 입력 차단 방식과 대조했다. KO 표시 명세에서 미정이었던 시간 종료/동시 KO/최종 승리 표현은 P3 승인 대상이며 아직 확정으로 변경하지 않았다. `ended`가 시간 종료를 표현하지 않는 현재 코드 차이는 경기 계층으로 처리하는 설계다.

자동 테스트는 양쪽 선수와 종료 경계 사례를 다룬다. 브라우저는 실제 버튼·키·포커스/탭 전환·시간 표시·결과 이미지 제거를 확인하고 증거를 남긴다. AI 없는 현재 단계의 실제 브라우저 검증과 자동 테스트로 구성한 CPU 승리/동시 KO 결과를 구분해 보고한다. Chrome/Edge 실제 실행 여부도 따로 기록한다.

## 10. 승인 후 진행 순서

1. 사용자 응답을 반영하고 이 문서의 승인 상태와 관련 결정 기록 갱신.
2. 경기 순수 로직과 M02~M13 중심 자동 테스트 구현.
3. 경기 검수 화면과 입력·로딩·결과 표시 연결, 기존 검수 화면 회귀 확인.
4. 브라우저 검수·명세/이미지/코드 정합성 점검, 결과·개발일지 기록, 기능 커밋.
