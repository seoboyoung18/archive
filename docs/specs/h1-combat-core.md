# H1 전투 판정 구현 단계

2026-10-01. [승인된 전투 v0.3](h1-combat-draft.md)을 구현한다. 새 기획·수치 변경은 없다.

## 범위와 완료 기준

화면에 연결하기 전에 선/앉은 공격8종·뒤 방향 방어·경직·밀려남·공중 피격·동시 타격·KO 후 정지를 순수 TypeScript 함수로 구현하고 자동 검증한다. 기존 이동/시안 화면과16포즈는 보존한다. 남은25포즈 생성과 애니메이션 연결, 타이머·승수·AI·브라우저 전투는 후속 단계이며 완료로 표시하지 않는다. 없는 포즈를 대기 그림으로 대체하지 않는다.

- U/I/J/K의 새 누름만 공격 명령. 다중 입력은 강발>강손>약발>약손. WASD 상쇄 후 자세를 결정하고 공격이 점프보다 우선한다.
- 준비/유효/회복은 명세의 반열린 구간. 시작 갱신 나이0, 다음 갱신부터 증가하며 총 길이에 도달한 갱신부터 새 행동이 가능하다.
- 타격은 양 축의 양수 겹침일 때만 발생한다. 좌향 판정은 루트 기준 반전한다. 공격 인스턴스별 선수ID 이력에 방어도 기록한다.
- 이동/접촉 이후 양쪽 판정을 같은 스냅샷에서 수집하고 피해를 함께 적용한다. 피격으로 취소되는 공격도 해당 갱신의 유효 타격은 처리한다.
- 공격과 피격은 자세·방향을 잠근다. 방어 경직은 현재 아래 입력으로 자세를 바꿀 수 있고, 뒤를 놓으면 후속 공격을 자동 방어하지 않는다. 피격 중 재타격에는 새 경직을 적용한다.
- 경직N은 피격 처리 이후 N번의 갱신 동안 행동을 막는다. 잔여0으로 끝난 갱신까지 막고 그 다음 갱신부터 행동한다. 해당 기간의 공격/점프 펄스는 소비하고 예약하지 않는다.
- 공격/경직 중 수평 입력은0, 공중 중력은 유지한다. 공중 공격·방어·예약 공격 없음. 공중 피격 자세는 선 자세이며 착지 후에도 피격 자세를 경직 만료까지 유지한다.
- 체력0은 KO 우선. 양쪽 타격을 모두 적용한 뒤 종료 표시를 만들고 이후 갱신은 모든 전투 상태를 그대로 반환한다. KO 연출·시간 종료·승수는 경기 계층의 후속 책임이다.
- 잘못된 공격 구간/수치/사각형은 전투 생성 전에 오류로 거절한다. UI 실패 안내는 화면 통합 때 연결한다.

## 설계·정합성

`src/characters/h1.ts`에 승인 수치와 자세별 공격 데이터를 둔다. `src/combat/combat.ts`는 캐릭터 정의를 받아 전투 상태를 생성·갱신한다. 기존 `stepMovement`로 중력/이동/선수 접촉을 처리하고 행동 잠금은 전투 계층에서 적용한다. 정의는 공유하지만 체력·공격ID·상대 이력은 선수별로 독립적이다. 입력 모듈은 기존 이동 입력을 합성하여 U/I/J/K 펄스를 더한다. Phaser·DOM·새 패키지는 추가하지 않는다.

전투 함수는 실제 처리한1F당 한 번 호출한다. 재생용 포즈 구간 조회와 타격 유효 구간은 같은 공격 나이를 사용한다. 8공격의 그림ID와 실제 파일 연결은 이미지 검수 이후 한다.

## 실행 계획·검증

1. 데이터8종을 원문 표와 대조하고 잘못된 값의 거절 경로 작성.
2. 입력/상태/판정 구현 후 준비·유효 첫/끝·회복 경계, 미접촉/1px 겹침/좌우 대칭 테스트.
3. 단타 중복·방어9조합·자세 고정/변경·경직 정확한N회·취소/동시 타격·공중/코너/KO 불변 테스트.
4. 실제 키 이벤트에 해당하는 입력 기록으로 유지/반복/다중키/초기화와 예약 없음 검증. 여러 렌더 간격에서 같은 논리 입력 기록의 결과 비교.
5. 기존15테스트 회귀·타입 검사·빌드·에셋 검사 후 검수 결과/개발일지/계획 동기화 및 기능 커밋. 실제 브라우저 전투 확인은 미수행으로 남긴다.
