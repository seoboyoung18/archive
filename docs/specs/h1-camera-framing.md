# H1 공통 화면 좌표 · 거리 대응 카메라 A

2026-10-03 · 사용자가 비교 화면을 보고 **“A · 거리 대응 카메라 적용 (권장)”**을 선택했다. A를 표적·AI 경기의 구현 기준으로 확정한다. 아래 B는 미채택 비교안이며, `3fe3f23`의 개별/쌍 표시 보정을 A의 공통 카메라로 대체한다.

## 문제와 제약

[이전 보완](h1-grab-edge.md)은 대기·방어·피격/KO와 잡기 그림을 경계 안으로 옮겼다. 걷기/점프/기본 공격은 논리 루트에 남아 있어 코너에서 상태를 바꿀 때 표시 루트가 달라진다. 각 포즈나 각 동작의 합집합으로 보정 범위를 늘려도 동작 사이의 차이는 남는다.

기본 공격까지 개별 이동시키면 [선 강발의 발끝 판정](h1-heavy-kick-contact.md)과 그림이 그 이동량만큼 어긋난다. 판정 선만 그림 쪽으로 옮기는 방식도 실제 전투 접촉과 다른 표시가 되므로 채택하지 않는다. 기존 [애니메이션 규격](h1-animation-draft.md)의 원점·배율·고정 발 정렬과 함께 검토해야 한다.

전 요소를 같은 거리만큼 옮기는 방식은 접촉 관계를 보존하지만, 양 끝에 선 대기 포즈만으로도 알파 범위가[-14.375,1294.375]라1280폭을 넘는다. 모든 경우의 잘림을 없애면서 그림과 판정을 맞추려면 화면에서 보이는 크기 또는 표시 영역을 바꿔야 한다. 이는 이전의 개별 표시 오류 수정과 다른 화면 규칙이며 위 사용자 선택으로 A를 확정했다.

## 비교 시안

[비교 화면](../reviews/evidence/h1-camera-review.html)은 초기 위치를 지정한 공통 전투 입력 재현이다. 적용 전 방식, 적용한 거리 대응 카메라, 미채택 고정 전체 보기의 세 모드를 같은 상태에서 비교한다. 적용 전 함수는 동결하고 A는 제품 함수를 사용한다.

- 코너: 벽 후진48틱 → 대기 → 제자리 점프 → 착지 → 선 강발 → 복귀. 왼쪽/오른쪽을 비교한다.
- 양 끝: 루트80/1200에서 기본8공격의 준비·유효·회복·종료를 확인한다.
- 거리 변화: 한 선수만 양 끝에서 근접까지 접근했다 후퇴한다. 거리896의100% 줌 경계를 양방향으로 통과하며 실제 화면 이동과 크기 변화를 비교한다.
- 근접: 거리84에서 메치기·풀기 전후의 원래 연출과 공통 표시를 비교한다.
- 그림·이름표·논리 발 기준점·공통 `worldRect`의 실제 공격/피격 사각형을 함께 표시한다. 체력과 안내 등 화면 UI는 고정한다. 실제 키 조작·사람의 체감 검사와 구분한다.

## 확정 A · 거리 대응 공통 카메라

1. 이미지의 월드 배율0.625와 모든 전투 좌표·판정·거리·피해·시간표·포즈·원화는 유지한다. 현재 개별/쌍 경계dx를 제거한 원래 연출에 하나의 화면 변환을 적용한다. 메치기의 기본 곡선·회전·높이는 유지한다.
2. 같은 화면 변환을 두 캐릭터·판정·발 기준점·이름표·배경에 적용한다. 이미지와 판정의 상대 위치 및 두 선수 사이의 전투 좌표 관계가 유지된다. 별도의 발 미끄럼 보간·카메라 흔들기·공격 확대를 추가하지 않는다.
3. 현재 H1의 실제 PNG와 원래 메치기 연출에서 측정한 루트 좌우 최대191.645576927px를 올림한 **M=192px**를 사용한다. 현재 포즈마다 M을 바꾸지 않는다. 실제 선택94포즈의 정적 범위는132.5px지만 공중 메치기H35의 이동/회전을 포함하면 더 커진다. [측정 근거](../reviews/evidence/h1-camera-measurements.json)에 원화와 표본을 보존한다.
4. 논리 루트의 최소/최대에 M을 더한 구간을[L,R]라 하면 `z = min(1, 1280 / (R-L))`다. 가까울 때 원래 크기를 유지하고 두 선수가 멀리 떨어져 필요한 경우에만 전체를 축소한다. 확대는 하지 않는다.
5. 화면x는 `640 + (worldX-640) * z + pan`이다. 변환된[L,R]가0~1280에 들어오는 최소 절댓값 pan을 쓴다. 화면y는 `600 + (worldY-600) * z`로 지면 높이를 유지한다. 동작 종류·포즈 나이·렌더 경과시간은 z/pan 입력이 아니다.
6. 같은 논리 위치에서 대기/보행/공격 포즈만 바뀌면 화면 루트와 카메라는 같다. 실제 이동·타격 밀려남·잡기 착지/분리로 논리 위치가 바뀌면 그 결과를 표시한다. 정지·종료 스냅샷은 같은 상태에서 같은 카메라를 반환한다.

양 끝80/1200의 최대 간격에서는 표시 여유를 포함한 폭1504를1280에 담아 **85.1064%**로 보인다. 기본 키240은 화면 기준 약204.255로 줄어든다(최대 약14.9% 축소). 기본 월드 배율0.625를 바꾸는 것은 아니지만 사용자에게 보이는 크기는 바뀌므로 이를 ‘배율 불변’만으로 설명하지 않는다. 중앙의 초기400/880과 근접에서는100%를 유지한다.

## 미채택 비교안 B · 고정 전체 보기

동일한 공통 변환을 사용하되 항상 논리 루트 범위80~1200과 M으로 계산한다. 화면 이동과 줌 변화가 없지만, 중앙 근접 대전에서도 캐릭터가 축소된 크기로 보인다. 비교 화면에만 남기고 게임에는 적용하지 않는다.

## 구현·검증 범위

선택한 A는 중앙 근접의 기존 크기를 유지하고 코너의 그림/판정 정합성과 상태 전환을 함께 해결한다. Phaser 월드 카메라의 원점은(.5,600/720), zoom은z, scrollX는-pan/z, scrollY는0이다. 제목·KO·경기 결과는 별도 항등 카메라에 두고 양쪽 카메라의 ignore 목록으로 중복 표시를 막는다. 바닥 그림은 축소해도 화면을 채우도록 연장하며 실제 지면600은 유지한다.

제품의 두 전투 화면에 공통 변환을 연결하고 기존 개별 보정 검사와 문서를 새 규칙으로 동기화한다. 전체 포즈/회전 경계, 좌우·양 끝·중앙, 기본8공격과 발끝 사각형, 코너 전환 루트, 잡기/풀기·KO/시간 종료·정지, 전투 결과 불변을 검증한다. [검수 기록](../reviews/h1-camera-framing.md)에 순수 검사·Phaser 연결·브라우저 관찰을 구분하며 실제 대전 난이도·청취·독립 브라우저 검수는 별도로 남긴다.
