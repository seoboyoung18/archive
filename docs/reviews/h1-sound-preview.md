# H1 효과음 S1 청취 시안 검수

2026-10-03 · 사용자 “좋다 다음 계속해서 진행하자”에 따라 [S1 제작 범위](../specs/h1-sound.md)를 진행했다. 시작 커밋은 `716673e`다. 메치기 결과에 대한 긍정 응답을 기록하며, 독립 브라우저·전체 모션 품질 검사를 새로 통과한 것으로 확대하지 않는다.

## 범위

손발4종·방어·헛침·붙잡음·바닥 충격·풀기9종을 직접 합성하고 [청취 화면](../../sound.html)을 추가했다. 화면은 개별·전체·조합 듣기, 시안 음량30%와 정지/Esc, 새 클릭 시 교체, 포커스/탭 이탈 및 음량0에서 예약 폐기를 제공한다. 실행 전에는 재생하지 않는다. fetch 누락은 해당 카드를 비활성화하고 디코딩/활성화 실패는 안내하며 준비된 다른 소리는 사용할 수 있다.

현재 전투 입력·체력·판정·시간·CPU 코드를 변경하지 않았다. 게임 두 화면은 계속 무음이다. 음색·길이·상대 음량 및 게임 기본 활성/초기 음량을 들은 뒤 선택하고 S2에서 사건에 연결한다. 파형 수치나 브라우저 재생 상태를 실제 기기에서 귀로 들은 품질 승인으로 간주하지 않는다.

## 제작 기록

[합성 스크립트](../../scripts/generate-h1-sounds.mjs)와 [검사 스크립트](../../scripts/verify-sounds.mjs), [WAV·설정 manifest](../../assets/audio/h1/s1-v1/manifest.json)에 고정 seed·합성 설정·해시·길이·피크/RMS·페이드·첫끝 샘플을 보존한다. 외부 게임 음원, 음성, 음악은 사용하지 않았다. 비교 reel은9종을 간격을 두어 순서대로 모은 청취 자료이며 추가 게임 슬롯이 아니다.

최초 강손 시안의 PCM 피크0.5699768066을 같은 시각에 두 번 합하면1.1399536132로 디지털 범위를 넘었다. 개별 파일 검사만으로 발견할 수 없는 조합 문제다. 모든 시안의 상대 크기를 유지해 합성 출력 단계에0.8을 적용했다. 약손·강손·방어는 시작1ms 인접 샘플 변화 검사에 맞춰 시작 페이드를3ms로 보완했다. 이는 청취 클릭 잡음이 완전히 없다는 주장과 다르다. 미리듣기 슬라이더에는 숨은 추가 감쇠나 리미터를 넣지 않았다. 파일의 제작값은 최종 게임 음량 선택과 구분한다.

## 조합과 비동기 재생

콤보는 공통 전투에 거리100과 보통 입력 U(F0)/I(F3)/J(F14)를 주어 명중F6/19/30을 얻었다. 첫 명중 기준0/13F/24F, 즉0/216.667/400ms다. 실제 입력 키 사이 간격과 혼동하지 않는다. 메치기 시안은 붙잡음0→바닥 충격600ms, H12 풀기 시안은0→200ms이며 H0 풀기는 풀기만 재생한다. 동시 타격은 같은 강손의 별도 재생 노드 두 개다.

`PreviewPlayer`는 사용자 클릭 안에서 오디오 활성화를 요청하고, 완료 후 실제 실행 상태를 확인한다. 디코딩은 파일별로 공유하지만 재생 인스턴스는 각 사건마다 만든다. 정지·교체·음량0·오디오 중단·종료는 요청 식별자를 갱신해 늦은 활성화/디코딩 완료를 폐기하고 현재/미래 예약 노드를 중단·분리한다. S2 사건 중복 방지나 게임 오디오를 검사한 것은 아니다.

## 검증 결과

- 최종 전체 `npm test` **197/197 통과**: 기존174 + 음원6 + 재생기14 + 시퀀스3. 활성화/디코딩의 늦은 완료·실패, 교체·정지·0음량·오디오 중단·종료, 동일 음원 동시 재생과 노드 정리, 부분 실패 식별을 fake Web Audio로 검사했다. 전체 신규 검사에 구현 전 사전 실패를 실행한 것은 아니다.
- `npm run build` 타입 포함 통과. `dist/sound.html`·9종 해시 WAV·비교 reel이 실제 빌드에 포함된다. 기존 Phaser 청크 크기 경고는 유지한다.
- `npm run verify:sounds`와 생성기의 `--check` 통과. PCM16/mono/48000·WAV 청크/샘플 수·해시·비무음·클리핑0·첫끝 샘플0·경계 변화와11파일의 바이트 단위 재현을 확인했다. 기존 `verify:assets`의100포즈 검사도 통과했다.
- 조합5개의 100% 선형 혼합 피크: 콤보0.455994, 동일 강손2개0.911987, 메치기0.511993, H12 풀기0.287994, H0 풀기0.287994. 이5개 조합에서 디지털 범위 미만이며 임의의 무제한 동시 재생이나 출력 장치의 왜곡까지 검사한 것은 아니다.
- 내장 브라우저의 실제 빌드4174에서9/9 음원 준비, 클릭 전 비활성, 전체 순서 재생 중 오디오 `running`/예약8개 관찰과 완료0개를 확인했다. 콤보·동시 타격·H36 메치기·H12 풀기·H0 풀기의5개 버튼 모두 재생 완료와 남은 예약0개를 확인했다. 이는 오디오 처리 상태 검증이며 실제 출력기기로 듣는 주관적 음질 검증은 아니다.
- 개발 화면4175에서 전체 재생→정지 버튼의 예약0을 확인했다. 빌드 화면에서 재생 중 음량0, 0에서 새 재생 요청 차단,30% 복원 후 자동 재생 없음도 확인했다. 처음에는0→30 복원 뒤 ‘음량0’ 안내가 남아 수정했고, 최종 빌드에서 ‘음량을 복원했습니다’·오디오 미생성·예약0으로 재확인했다.
- 실제 탭 전환 검수는 앱의 열기 요청이 대기 상태로 남아 포커스 이탈을 재현하지 못했다. 포커스/탭 이벤트 연결과 취소 처리의 자동 검사는 실제 탭 이탈·복귀 성공으로 보고하지 않는다. 실제 브라우저의 파일 누락·디코딩 실패·활성화 실패를 강제로 재현하지 않았으며 해당 경로는 자동 검사 범위다.
- 최종 빌드 탭의 warn/error는0이었다. [청취 화면](evidence/h1-sound-preview.png)과 [H0 풀기 완료·조합 화면](evidence/h1-sound-sequences.png)에 화면 근거를 저장했다.

## 남은 선택

사용자의 실제 청취 후 음색·강약·소리 길이·반복 피로도, 게임 기본 소리 활성 여부와 초기 음량을 선택한다. 독립 Windows Chrome/Edge와 출력 장치의 실제 청취 품질, S2 게임 사건 연결 및 실제 대전 소리는 아직 미확인이다.
