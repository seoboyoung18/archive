# 첫 3명 R0 기준 자세 검수 · 2026-10-06

[첫 3명 명세의 R0 실행 기준](../specs/initial-roster.md)에 따라 B1·R3의 단일 기준 이미지를 원본 보존 상태로 정렬했다. [비교 화면](evidence/roster-r0.html)과 [전체 화면 증빙](evidence/roster-r0.png)은 H1 현행 대기 그림과 나란히 보는 **외형 후보**다. B1/R3는 아직 게임에서 선택하거나 움직일 수 없다.

| 항목 | H1 현행 대기 | B1 R0 | R3 R0 |
|---|---:|---:|---:|
| 출력 | 512×512 RGBA | 512×512 RGBA | 512×512 RGBA |
| 알파≥8 머리~발 y | 64~447 | 73~447 | 70~447 |
| 알파≥8 가로 x | 106~412 | 89~437 | 111~411 |
| 발 바로 아래 | y448 | y448 | y448 |
| 표시 배율 | 0.625 | 0.625 | 0.625 |

원본의 알파>0 높이를 384px로 비율 유지 축소하고 원본 캔버스의 가로 중점을 x256으로 맞췄다. 고품질 보간 뒤 알파≥8 발끝을 y447에 맞추기 위해 B1을 8px, R3를 2px 아래로 보정했다. 원본의 희미한 테두리(알파1)는 두 출력 모두 y449까지 남는다. 이는 투명도 8 미만의 리샘플링 흔적이며 시각적 발 접지 기준은 아니다. 부위 재그림·가로 잘림은 하지 않았다. 정확한 원본/출력 SHA-256, 배율, 오프셋, 알파 경계는 [B1 기록](../../assets/characters/b1/derived/r0/manifest.json)과 [R3 기록](../../assets/characters/r3/derived/r0/manifest.json)에 있다.

첫 배치에서 나타난 발 높이 차이와 보정 근거는 [Notion 트러블슈팅](https://app.notion.com/p/3f1a2fe05e68818e9409d6cf1c2d828f)에 `(정형수치문제)`로 기록했다.

검증: 정렬 스크립트를 재실행했을 때 두 출력 SHA-256가 각각 `b22340e1…91bb018`, `2c785b67…785fe3`으로 동일했다. 원본 SHA-256도 각 기록과 일치했다. 두 출력 모두 512×512, 투명 RGBA, 알파≥8 하단447이며 가로 영역이 캔버스 안에 있다. PC 브라우저의 실제 비교 화면에서 H1/B1/R3 세 이미지가 512×512로 로드되고 같은 지면에 표시되는 것을 확인했다. 비교 탭의 경고·오류 로그는 없었다. TypeScript 검사 포함 `npm run build`가 통과했고 기존 대용량 청크 경고는 유지됐다. 2026-10-06 사용자가 **현재 B1·R3 크기와 외형 시안을 승인**했다.

미확인: 실제 대전 화면에서 움직일 때의 B1/R3 동작 연속성·판정·카메라 경계, 캐릭터 선택과 AI 조합. R0 기준 자세 하나로 애니메이션 또는 플레이 적합성을 확인했다고 해석하지 않는다. [B1 상태→포즈 초안](../specs/b1-pose-r1.md)은 작성했고 능력치·CPU 선택 및 그림 제작 범위는 사용자 결정이 남았다.
