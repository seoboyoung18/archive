# H1 CPU 잡기·풀기 구현 검수

2026-10-03 · AI-G v0.1. [상세안](../specs/h1-ai-grab.md)에 대한 사용자 **“이 안으로 구현 (권장)”** 응답 후 구현했다. 비교 기준은 `94c9eff`의 [구현 전 재현](h1-ai-grab-baseline.md)이며, 승인 문서 커밋은 `2829de2`다.

## 구현 범위

- CPU는 자유로운 지상 상태에서 보이는 앉기·선 방어/후진에 접근한다. 거리96 안의 자유 대상에게 기존 U+I 잡기를 보내고, 방어 경직 중인 대상에게는 기다린다. 보이는 공격에 대한 방어와 자신의 행동 잠금은 먼저 처리한다.
- 시도부터120F 동안 다음 잡기를 막는다. 실패·풀림에도 같은 대기이며 그동안 기존 기본기를 사용한다. 접근/풀기는 잡기 대기를 새로 설정하지 않는다.
- CPU가 정상12F 판단에서 관찰한 첫 성공 잡힘은 허용하고, 두 번째부터 번갈아 새 U+I로 한 번만 풀기를 시도한다. 소유자+ID로 같은 관계의 중복을 막으며 ID 크기나 PLAYER의 현재 키·체력·예약을 전략에 쓰지 않는다.
- 자기 성공 잡힘의 H0~12만 기존 잠금 중 관찰 예외다. 관찰H11의 명령은 공통 갱신H12에 풀리며, 관찰H12의 명령은H13으로 늦어 실패한다. 대상 그림이H19까지 붙잡힌 자세라는 이유로 풀기 창을 늘리지 않았다.
- CPU가H54에 먼저 복귀해도 상대H72 전에는 대기한다. 정지는 정책/시계를 보존하고 유지 입력만 지운다. 종료 후 고정, 새 라운드·동률 재경기·전체 재시작은 모두 초기화한다.
- 공통 전투 수치·포즈100개·음원9종·오디오 처리기는 유지한다. CPU도 공통 잡기/풀기 사건을 내므로 기존 붙잡음·충격·풀기 소리가 그대로 연결된다. 경기 안내와 접힌 검수 수치에 새 행동을 반영했다.

## 동일 PLAYER 정책 비교

표준 시작 P400/CPU880·HP100·60초·2선승·커서0에서 각각3회 재실행했다. PLAYER 함수는 기준 자료와 동일하다. 각 반복은 같은 결정론적 입력이므로 3개 난수 시드나 사람 표본이 아니다. 아래 시간은 **라운드별 실제 playing 논리F/60**이며 두 라운드 결과가 같았다. 결과 연출·수동 라운드 전환 시간은 포함하지 않는다.

- 보존 경로의 스크립트 재실행은 JSON 바이트까지 동일했다(SHA256 `daa58129fb7579f6af13452910472ca68bc01cfdfb8577f00aac016b3ab6dc71`). 원래 임시 실행 자료와 결과/소스 해시는 동일하며 비교 기준 경로 메타데이터만 보존 위치로 바꿨다.
