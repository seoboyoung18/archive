## Git 컨벤션 검토 · 커밋·push 보류

- 사용자가 Git 컨벤션을 먼저 맞추기 위해 커밋·push를 중단했다. 제공한 ZIP의 `Convention` 문서에는 링크 5개가 있어 연결된 Notion의 Branch·Commit·Pull Request·Issue·Code 문서를 조회했다.
- 확인된 커밋 형식은 `태그: 작업 내용 (#이슈번호)`이며 태그 첫 글자는 대문자, 이슈 번호는 선택 사항이다. 현재 `codex/h1-opposite-limbs`의 미반영 17개 커밋은 소문자 태그를 사용한다. HEAD는 `f4181be`이며 이력은 변경하지 않았다.
- 원문 충돌: Branch 문서는 통합 브랜치를 `develop`, PR 문서는 `dev`로 표기한다. 기능 브랜치도 규칙 문장에는 `feat/`, 종류·예시에는 `feature/`가 사용된다. `dev`와 `feature/이슈번호-기능명`으로 통일하는 안을 제안하고 사용자 선택을 요청했다. 아직 확정하지 않았다.
- PR 문서는 `[태그] 작업 요약 (#이슈번호)` 제목, 본문 템플릿, 리뷰 승인 후 squash merge를 안내한다. 전체 팀원 승인/1명 이상 승인 및 제목 태그 표기에 차이가 있어 프로젝트 규칙 정리 시 구분해야 한다. 원문의 다른 프로젝트 연결 지시와 Java 전용 코드 규칙은 차원격투에 자동 적용하지 않았다. Issue 조회에는 라벨 생성 예시 블록 1개 누락 표시가 있어 전체 원문을 완전히 읽었다고 간주하지 않는다.
- 검증: ZIP 내부 Markdown과 Notion 5페이지, 현재 브랜치·커밋 목록·작업 트리를 확인했다. 검토 시작 시 작업 트리는 깨끗했다. 이번에는 개발일지만 갱신하며 코드 변경·테스트 재실행·커밋 수정·push·원격 설정 변경은 수행하지 않았다.
- 다음: 명칭 선택을 반영해 프로젝트 컨벤션과 기존 로컬 이력 정리안을 마련한다. 사용자가 중단한 커밋·push는 보류 상태를 유지한다.
