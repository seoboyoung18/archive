# H1 전투 설계 초안 v0.2

상태: 제안. [전투 명세](../specs/h1-combat-draft.md)와 [애니메이션 명세](../specs/h1-animation-draft.md)의 세부안 승인 및 엔진 선정 전이다. 구현 파일명·패키지 구조를 확정하지 않는다.

## 책임 분리
| 역할 | 책임 | 하지 않는 일 |
|---|---|---|
| 사용자 입력 / AI | 동일한 좌우·아래 방향 유지 입력과 약손·강손·약발·강발·점프 1회 명령 생성 | 직접 이동·피해 적용, 전용 방어 명령 |
| 전투 갱신 | 고정 시간 이동·상태·공격·피해·경직·방향 처리 | 이미지 크기로 판정 추정 |
| 경기 진행 | 라운드 시작·정지·결과·승수·다음 라운드·재경기·경기 종료·재시작·제한 시간 | 캐릭터별 전투 코드 복제 |
| 캐릭터 데이터 | 체력·속도·판정·공격 구간·애니메이션 참조 | 캐릭터마다 동일 로직 중복 |
| 화면·에셋 | 상태에 맞는 포즈·체력·결과 표시, 로딩 검증 | 렌더 시간으로 피해 결정 |

## 최소 데이터
- 캐릭터 정의: ID, 표시 이름, 기본 체력, 이동·점프 값, 자세별 피격 사각형, 약손·강손·약발·강발 각각의 피해·경직·밀려남·사각형·구간 길이, 포즈 참조·발 기준점·배율. 앉기·상중하단 관련 값은 세부 규칙 확정 후 구체화한다.
- 선수 실행 상태: 선수 ID(캐릭터 ID와 구분), 캐릭터 정의 참조, 체력, 위치·속도·방향·지상 여부, 행동 상태·경과 시간, 경직 잔여 시간, 공격 ID·타격 상대 이력.
- 경기 실행 상태: 단계, 두 선수, 라운드 번호, 양쪽 승수, 남은 라운드 논리 시간, 라운드 결과, 경기 결과, 누적 논리 시간, 입력 추적, AI 판단 시간, 종료 연출 시간.
- 뒤 방향은 상대 위치와 현재 방향으로 공통 입력 처리에서 계산한다. 서 있기/앉기 및 행동 제약과 함께 방어 자격을 산출한다. AI도 전용 방어 플래그로 이 규칙을 우회하지 않는다.
- 다음 라운드 및 예외 재경기에서는 승수를 보존한다. 승패가 난 경우에만 라운드 번호를 증가시키며, 재경기는 같은 번호를 쓴다. 경기 전체 재시작만 승수까지 0으로 돌린다. 2승 검사 후 다음 라운드 생성 여부를 결정한다.
- H1 두 선수는 정의를 공유하되 체력·상태·타격 이력은 공유하지 않는다. 새 캐릭터가 기존 행동만 쓰면 정의와 이미지를 추가해 적용한다.
- 서버·DB·로그인·네트워크 동기화·범용 플러그인 시스템은 만들지 않는다. 첫 단계의 직접적인 역할 분리만 사용한다.

## 정합성 검토
| 검토 대상 | 문서 검토 결과 | 남은 검증 |
|---|---|---|
| 초기 캐릭터 3명 ↔ H1 우선 | H1은 중간 검증 단계로 명시, 3명 선택 목표 유지 | B1/R3 선택 상세 흐름 |
| 입력 ↔ 상태 | WASD·뒤 방향 방어·공격 4종, 뒤+공격 시 공격 동안 방어 자격 없음 | 실제 키·포커스, 앉기·상중하단·동시 입력 제안 확정 |
| 공격 ↔ 그림 | 약손 6+3+15=24F, 강손 10+3+21=34F, 약발 8+4+18=30F, 강발 12+4+24=40F. 각각 3포즈 | 실제 타격 포즈·판정, 기본 26포즈/앉기 포함 28포즈 제안 검토 |
| 표시 ↔ 좌표 | 원화 높이 384 × 0.625 = 표시 키 240. 피격 높이 220은 별도 기준 | 실제 원화 정렬·외형 적합성 |
| 거리 ↔ AI | 가로 겹침 경계 140/160/170/190, 각각 8픽셀 안쪽 132/152/162/182의 공격 선택 제안 | 움직임·앉은/공중 상대·상중하단 반영 |
| 시간 초과 ↔ 라운드 결과 | 낮은 체력은 패배. 동일 체력·동시 KO는 승수 변화 없는 재경기 | 마지막 갱신 타격, 동일 번호 재경기 |
| 라운드 ↔ 경기 | 2:0 조기 종료, 1:1 후 승자 2:1 종료. 예외 재경기는 실제 3회 초과 허용 | 중복 승수 방지 및 불필요한 다음 라운드 없음 |
| 일시정지 ↔ 초기화 | 라운드 전환은 승수 유지, 경기 재시작은 승수 포함 초기화 | 반복 실행 및 입력·상태 누수 |

이 표는 문서상 검토다. 실제 이미지·코드가 일치한다고 검증한 결과가 아니다.

## 구현 순서와 검증 계획
1. 세부 명세 승인 → 웹 실행·프레임 애니메이션·테스트 용이성을 기준으로 기술 후보 비교/선정 → .gitignore와 실행 환경.
2. 대기 정규화 및 약손 3포즈 시안 → 발 기준점·색상·판정 관계 검토 → 강손·약발·강발 등 나머지 포즈 제작. 앉기 관련 규칙은 해당 포즈 제작 전 확정.
3. 공통 입력·고정 시간·이동·경계·점프 → 전투 V01~V03/V11 검증.
4. 공격 4종·뒤 방향 방어·피격·동시 타격 → V04~V08/V19~V21 및 포즈 타이밍 검증.
5. 라운드·승수·경기·시간·일시정지·재시작·실패 처리 → V09~V15/V18/V22 검증.
6. AI와 브라우저 통합 → V16~V17 및 Chrome/Edge 실제 플레이. 미검증 품질은 별도 기록.
7. H1 흐름 검증 후 B1/R3의 규격·능력치·선택 흐름 확정 및 데이터로 적용.

기술 선택 전까지 빌드 명령과 테스트 도구를 임의로 정하지 않는다. 위 단계별로 문서·코드·개발일지를 동기화하고 커밋으로 되돌릴 지점을 남긴다.
