# H1 전투 설계 초안 v0.3

상태: [전투 명세](../specs/h1-combat-draft.md)와 [애니메이션 명세](../specs/h1-animation-draft.md)가 초기 기준으로 승인됐다. C/G 최초 구현 이후 사용자 요청과 “권장 시간표로 수정” 승인에 따라 [회전 메치기·H0 풀기](../specs/h1-throw-revision.md)를 적용했다. 현재는 H36 피해18·공격자H54/대상H72 복귀·100포즈를 사용하며 아래 최신 메치기 설계가 이전 밀치기 G 이력을 대체한다. 검증 결과는 [메치기 검수 기록](../reviews/h1-throw-revision.md)을 따른다. 메치기 결과 확인과 다음 진행 요청에 따라 [S1 효과음 청취 시안](../specs/h1-sound.md)을 제작하고 자동 검사·내장 브라우저 재생 상태를 확인했다. S2 게임 연결·최종 음색/게임 초기 음량과 CPU 새 기술 선택은 후속 확인 대상이다. 기술은 Phaser 4 + TypeScript + Vite다. 초기 실행 환경·이미지 시안 작업은 [별도 작업 명세](../specs/h1-asset-preview.md)를 따른다.

기술은 일반 격투게임의 성공 동작·판정·상대 반응·실패·대응 수단·회복을 함께 설계하고 검수한다. 회전 메치기를 붙잡았다 놓는 동작으로 대체하지 않으며, 특정 게임의 고유 수치/기능은 별도 결정 없이 가져오지 않는다.

## 최소 데이터
- 캐릭터 정의: ID, 표시 이름, 기본 체력, 이동·점프 값, 선/앉은 피격 사각형, (자세, 약손·강손·약발·강발) 조합으로 찾는 공격 8종의 방어 종류·피해·경직·밀려남·사각형·구간 길이, 포즈 참조·발 기준점·배율. 수치 제안은 전투 명세에 둔다.
- 선수 실행 상태: 선수 ID(캐릭터 ID와 구분), 캐릭터 정의 참조, 체력, 위치·속도·방향·지상 여부, 선/앉은 자세, 행동 상태·경과 시간, 경직 잔여 시간, 공격 ID·시작 자세·타격 상대 이력, 피격 시 자세. C에는 연계 단계·비방어 명중 자격·지정 다음 키 예약 여부를, G에는 손 유지/누름F/대기·잡기 역할/나이/대상 자세와 종료 표시용 스냅샷을 선수별로 둔다. 전투 전체가 성공한 한 쌍의 관계와 붙잡음/충격/풀기 사건을 보유한다.
- 경기 실행 상태: 단계, 두 선수, 라운드 번호, 양쪽 승수, 남은 라운드 논리 시간, 라운드 결과, 경기 결과, 누적 논리 시간, 입력 추적, AI 판단 시간, 종료 연출 시간.
- 뒤 방향은 상대 위치와 현재 방향으로 공통 입력 처리에서 계산한다. 서 있기/앉기 및 행동 제약과 함께 방어 자격을 산출한다. AI도 전용 방어 플래그로 이 규칙을 우회하지 않는다.
- 입력 처리는 반대 방향 상쇄·현재 자세와 행동 자격을 확인하고 C/G 명세에 따라 기본기·손 대기·잡기/풀기를 판독한 뒤 이동/점프를 처리한다. 방어 판정은 사각형 접촉 후 일반/중단/하단 표와 뒤 입력으로 계산한다. 공격/피격/잡기 중 자세는 고정하고, 방어 경직 중에는 현재 S에 따른 자세 전환을 허용한다.
- 다음 라운드 및 예외 재경기에서는 승수를 보존한다. 승패가 난 경우에만 라운드 번호를 증가시키며, 재경기는 같은 번호를 쓴다. 경기 전체 재시작만 승수까지 0으로 돌린다. 2승 검사 후 다음 라운드 생성 여부를 결정한다.
- H1 두 선수는 정의를 공유하되 체력·상태·타격 이력은 공유하지 않는다. 새 캐릭터가 기존 행동만 쓰면 정의와 이미지를 추가해 적용한다.
- 서버·DB·로그인·네트워크 동기화·범용 플러그인 시스템은 만들지 않는다. 첫 단계의 직접적인 역할 분리만 사용한다.

## 구현 순서와 검증 계획
1. 명세·기술 선정 완료 → .gitignore와 실행 환경, 에셋 시안 화면 준비.
2. 대기 정규화 및 선 약손 3포즈 시안 → 발 기준점·색상·판정 검토 → 앉기·앉은 약발 시안 검토 → 선/앉은 나머지 동작 제작. 이미지 규격과 수치 제안은 제작 전 검토.
3. 공통 입력·고정 시간·이동·경계·점프 → 전투 V01~V03/V11 검증.
4. 선/앉은 공격 8종·뒤 방향 방어·피격·동시 타격 → V04~V08/V19~V21/V23~V28 및 포즈 타이밍 검증.
5. 라운드·승수·경기·시간·일시정지·재시작·실패 처리 → V09~V15/V18/V22 검증.
6. AI와 브라우저 통합 → V16~V17 및 Chrome/Edge 실제 플레이. 미검증 품질은 별도 기록.
7. H1 흐름 검증 후 B1/R3의 규격·능력치·선택 흐름 확정 및 데이터로 적용.

빌드 도구는 선정된 Vite와 TypeScript를 사용한다. 위 단계별로 문서·코드·개발일지를 동기화하고 커밋으로 되돌릴 지점을 남긴다.

## 2026-09-30 구현 현황

[입력·이동 단계](../specs/h1-movement.md)를 별도 화면에 구현했다. `src/input/movement-input.ts`는 키 유지/누름/초기화, `src/combat/movement.ts`는 두 선수 이동·접촉·방향·자세, `src/combat/fixed-step.ts`는60Hz 누적을 담당한다. `src/movement.ts`가 Phaser 표시와 DOM 이벤트를 연결한다. 이동 수치는 공통 갱신 함수의 인자로 전달하며, 아직 필요하지 않은 전체 캐릭터/경기 구조는 만들지 않았다.

단위 테스트와 내장 브라우저 확인은 [이동 검수 기록](../reviews/h1-movement.md)에 있다. 이는 V01/V03/V11/V12/V14의 이동 관련 부분에 대한 증거이며, 공격·밀려남·경기 상태가 포함된 전체 조건의 통과를 뜻하지 않는다.

## 2026-10-01 전투 판정 구현

후속 [전투 화면](../specs/h1-combat-preview.md)은 `src/combat-preview.ts`에서 공통 전투 함수·입력·고정 시간과 Phaser 표시를 연결한다. `src/characters/h1-poses.ts`가41포즈 경로 및 전투 나이에 따른 그림을 선택한다. 검수용 상대 입력도 공통 입력 구조를 따르고 직접 피해를 조작하지 않는다. KO 뒤 전투 상태를 고정한 채 쓰러짐3장만6F씩 진행한다. 경기·AI 계층은 후속 구현이다.

[구현 단계 명세](../specs/h1-combat-core.md)에 따라 `src/characters/h1.ts`에 공격8종·피격 범위를 분리했다. `src/combat/definition.ts`는 데이터 타입과 시작 전 검증, `src/combat/combat.ts`는 공격 나이·이력·자세/방향 잠금·경직과 동시 타격을 처리한다. 이동/중력/접촉은 기존 `stepMovement`를 사용한다. `src/input/combat-input.ts`는 기존 방향 입력과 공격 펄스를 합성하며 예약 입력을 보관하지 않는다.

양쪽 타격을 먼저 수집하고 이력을 기록한 뒤 피해·경직·밀려남을 적용한다. 공격ID는 선수ID와 함께 식별한다. KO 후 전투 상태는 고정되며 쓰러짐 그림과 승수/시간 판단은 이후 경기·표시 계층에서 담당한다. [자동 검증 결과](../reviews/h1-combat-core.md)는 화면/이미지 적합성 검증과 구분한다.

## 2026-10-02 경기 진행 계층

승인된 [경기 진행 v0.2](../specs/h1-match-flow.md)를 `src/combat/match.ts`와 `src/match-preview.ts`에 구현했다. 순수 경기 상태가 시간/종료 우선순위/승수/전환을 관리하고 화면은 결과를 표시한다. 시간 종료에서 전투의 `ended=false`여도 경기 단계가 전투 호출을 차단한다. `paused`는 기존 단계를 보존하며 KO 연출만 전투 프레임과 분리한다.

Enter/Esc/R과 전환 입력 정리는 `src/input/match-input.ts`에서 기존 전투 입력을 재사용한다. 다음 라운드와 재경기는 새 전투 상태를 만들고 승수/번호만 계약에 따라 보존한다. 에셋 목록은 `h1-assets.ts`로 공유하며 공통 전투 판정 코드를 복제하지 않는다. AI는 미구현이며 강발 발끝에 맞춘 선택 명세부터 재검토한다.

## 2026-10-02 AI 연결 설계 · 승인·구현

승인된 [AI 대전 v0.1](../specs/h1-ai-match.md)을 `h1-ai.ts`와 `h1-ai-match.ts`로 분리했다. 전자는 판단 시계/유지 방향/아래/순환 위치와 명령 생성, 후자는 최소 공개 상태 투영·기존 경기 호출·전환 초기화를 담당한다. 화면도 자동 검사도 같은 연결 함수를 사용한다. 커서는 코드에서0부터, 문서에서는1부터 센다. 관찰 함수는12F 판단 시점에만 호출하며 PLAYER 키 버퍼를 전달하지 않는다.

전투 `worldRect`의 인자 타입만 실제 필요한 x/y/facing으로 좁혀 같은 사각형 함수를 재사용했다. 함수 실행 내용·공격 데이터·이미지·경기 규칙은 유지한다. AI 결과가 종료되면 그 틱에서 유지 입력을 비우고 이후 시계/커서를 진행하지 않는다. 명령에 의한 정지/라운드 전환도 같은 초기화 함수를 거친다. [검수 결과](../reviews/h1-ai-match.md)에 자동93개와 실제 플레이의 차이를 기록한다.

## 2026-10-03 C 콤보 설계 · 승인·구현

승인된 선 U→I→J를 사용자가2타 또는3타로 입력하도록 구현했다. 기존 공격 중 입력 폐기에서 지정 다음 키1개만 예외로 둔다. 단독 I·K·앉은/공중 연계, 자유 캔슬, G의 U+I/3F 손 판독, S 효과음과 CPU의 새 연계 선택은 범위 밖이다. [콤보 검수 기록](../reviews/h1-combo.md)에 총111개 검사와 실제 키/화면 결과를 구분했다.

| 영향 영역 | C 설계 |
|---|---|
| 캐릭터 정의 | 기본 공격8종 수치는 보존하고 허용 경로·입력/취소 창만 별도 정의. 존재하는 공격인지와 창 경계를 시작 전 검증 |
| 물리 입력 | 기존 공격 펄스/반복 차단/놓기 계약 유지. 손 입력 지연 없음. 전투가 명령을 읽어 지정 예약을 관리 |
| 순수 전투 | 기존 나이 증가 → 지정 예약/취소 → 기존 이동/접촉 → 양쪽 피해 순서. 후속 공격은 새ID·age0으로 시작. 접촉 이력과 비방어 명중 자격 분리 |
| 정지·경기 종료 | 정지는 예약만 제거하고 진행 단계/명중 자격 보존. KO/시간 종료/전환/초기화는 연계 전체 제거. 최종 포즈·마지막 피해는 보존 |
| AI 경계 | 공통 함수는 양쪽 같은 규칙. 기존 AI는 공격 중 펄스를 내지 않아 새 콤보를 쓰지 않으며 예약 정보를 관찰하지 않음 |
| 화면·모션 | 경기와 표적 검수에 조작 안내를 반영하고 기존 유효 마지막 포즈에서 다음 준비로 연결. 신규 그림 필요 여부는 시각 검수 후 판단 |

U는age3~12에 I를 예약하고age9~12에 취소한다. 그 연계 I만age5~22에 J를 예약하고age13~22에 취소한다. 모두 양 끝을 포함하며 명중 갱신 자체에는 취소하지 않는다. 방어·헛침·피격/상호 타격은 연계를 끝낸다. 창 밖·잘못된/다중 키 입력은 버리되 기존 올바른 예약은 보존한다. J 이후 정상 회복하고 자동 재시작하지 않는다.

1. 캐릭터 연계 정의와 순수 전투 상태/전이를 구현하고 C01~C04의 경로·프레임·거리·실패 분기를 검증한다.
2. 정지·포커스 상실·KO/시간 종료·라운드/재경기/전체 초기화에 예약 정리를 연결하고 C05를 검증한다.
3. 기존93개 회귀·타입·빌드·에셋 검사로 공격 수치·AI·경기 규칙 유지 여부를 확인한다.
4. 실제 키와 기존75포즈로2/3타·헛침·방어·취소 연결을 시각 검수한다. 자동 수치 검사와 최종 모션/난이도 체감 결과는 구분해 기록한다.
5. 검수 기록·개발일지·계획을 실제 결과로 동기화하고 검증된 작업 단위로 커밋·push한다.

## 2026-10-03 회전 메치기·H0 풀기 설계 · 수정 승인·구현

성공은 붙잡기 → 회전·들어 넘기기·낙하 → 바닥 충돌 → 다운·기상으로 표현한다. 승인된 H36 충격·피해18, 공격자H54/대상H72 독립 복귀를 공통 전투와 두 화면에 적용했다. 앞방향 착지·최종 이동48을 유지하고 좌우 위치를 교대하지 않는다. 기존94포즈/원본을 보존하고 `throw-v1`의6포즈를 추가했다.

| 영향 영역 | 현재 설계 |
|---|---|
| H0 입력 | 실제 한쪽 성립 후보가 있을 때 대상의 이전 손 의도를 지우고 현재F 누름/놓기를 기존 `readHands`의 풀기 모드로 판독한다. 선/앉은·일반 공격 중 대상도 새 U+I면 `escape` 1건만 발생한다. H0의 새 한 손은 H1~3 조합에 보존하며 H 이전 유지/반복은 제외한다 |

| 독립 잠금·다운 | 각 역할의 `releaseAt`으로 H54/H72에 해제한다. 관계는 두 복귀 시점의 최댓값까지 유지한다. H36~71 대상은 일반 타격 접촉과 새 잡기에서 제외하고 H72부터 정상 판정이다. 관계 정리는 먼저 복귀한 공격자의 새 공격/잡기를 취소하지 않는다 |

전체174개·타입/빌드·100포즈 에셋 검사는 통과했다. 실제 근접 배치 이후 키 조작과 연결 화면, 미확인 체감은 [메치기 검수 기록](../reviews/h1-throw-revision.md)에 구분한다. 사람의 최종 동작/입력/난이도 체감과 독립 Chrome/Edge 확인은 남는다.

## 2026-10-03 S1 효과음 청취 시안 설계 · 제작

사용자가 메치기 결과에 “좋다 다음 계속해서 진행하자”라고 답해 별도 `sound.html`과 직접 합성 WAV9종을 제작한다. 이 단계는 청취 비교용이며 공통 전투의 사건 생성·피해·시계·입력·AI와 `combat.html`/`match.html`의 무음 상태를 유지한다. 메치기 결과 확인을 모든 독립 브라우저·입력/난이도 체감 검증 완료로 보지 않는다.

| 영역 | S1 책임과 검수 기준 |
|---|---|
| 합성·에셋 | 손발4종·방어·헛침·붙잡음·바닥 충격·풀기를 PCM16·모노·48kHz로 합성. `assets/audio/h1/s1-v1/`에9개 WAV와 잠정 설정·측정 manifest 보존. `generate-h1-sounds.mjs`/`verify-sounds.mjs`로 재현·규격·파형·혼합 검사 |

S2에서 기존 `HitEvent`/`GrabEvent`와 추가할 헛침 사건을 각 논리틱마다 소비하는 설계는 [S 명세](../specs/h1-sound.md)의 후속 연결 목표로 유지한다. S1 제작값과 자동 검사 결과만으로 S2 승인이나 음질 통과를 선언하지 않는다.
